Title: NVIDIA's Nova Rust Driver Once Again Drives the Upcoming Linux 7.4 Graphics Changes
Content:
<p>The next wave of graphics-driver changes heading for the Linux kernel has been submitted for integration, and once again NVIDIA's Nova driver sits at the centre of the effort — this time as the practical testbed for Rust-based GPU drivers across the entire open-source graphics stack.</p>
<p>According to Phoronix, the Direct Rendering Manager (DRM) Rust changes targeting the Linux 7.4 merge window have been posted for pulling into DRM-Next, ahead of that development cycle opening. Nova, the in-kernel Rust driver NVIDIA has been building for its modern GPUs, continues to lead the way for Rust GPU drivers in the kernel and, in doing so, is fleshing out the shared Rust DRM infrastructure that other hardware vendors will eventually depend on.</p>
<p><strong>More than one vendor's project</strong></p>
<p>Nova is not merely an NVIDIA project. Because it is the most advanced Rust driver in the DRM subsystem, its development effectively funds the research and design work for the framework itself — the abstractions, traits and plumbing that let any vendor write a GPU driver in Rust rather than C. Other drivers built later will inherit much of that groundwork rather than starting from scratch. In open-source terms, Nova is the reference implementation.</p>
<p>That matters for a second reason: memory safety. The kernel community's broader push to rewrite performance-critical subsystems in Rust is, at its core, an argument about structural risk. Long-lived C code in the graphics stack has historically been a fertile source of memory-corruption bugs. A driver written in Rust moves an entire class of those bugs from "possible" to "largely prevented by the compiler" — a meaningful change for anyone running these drivers at scale.</p>
<p><strong>Firmware offload, from the ground up</strong></p>
<p>Nova's architecture is also worth understanding on its own terms. Like the existing open-source Nouveau driver's newer code paths, Nova leans on NVIDIA's GSP (GPU System Processor) firmware: offloading much of the driver's complexity to firmware running on the GPU itself, rather than replicating undocumented hardware behaviour in the kernel. The difference is that Nova was written in Rust from the start, whereas Nouveau is a long-standing C codebase that has been retrofitted to use GSP. Nova's development has been driven in large part by engineers on the company's open-kernel graphics team.</p>
<p>It should be noted that neither Nouveau nor Nova has displaced NVIDIA's proprietary driver for many production workloads; the proprietary stack remains the practical reference for demanding deployments. Nova's significance is that it is closing that gap in the open for the first time on modern NVIDIA hardware.</p>
<p><strong>Why the composition of the graphics stack matters</strong></p>
<p>For Hong Kong's fast-expanding AI and GPU-intensive datacentre buildouts, the composition of the Linux graphics stack is not a desktop concern. Datacentre operators choosing between proprietary and open kernel components are weighing supply-chain transparency, auditability and long-term maintainability against day-one performance. A memory-safe, upstream-maintained driver for widely deployed GPUs gives infrastructure teams a credible open option where none previously existed — particularly for GPU-intensive deployments such as AI buildouts across Asia, where server fleets are large enough that per-driver reliability compounds quickly.</p>
<p>The Linux 7.4 merge window is expected to open shortly, after which these changes will begin their journey through the mainline review process. If Nova again anchors the cycle's Rust work, it will reinforce a pattern now visible across several releases: NVIDIA, long the villain of the open-source graphics story, is writing the code that defines its future.</p>
<hr>
<p>新一波即將整合到 Linux kernel 的圖形驅動變更已提交審批，而 NVIDIA 的 Nova 驅動再次成為整項工作的核心——本次它更充當整個 open source 圖形技術堆疊中 Rust GPU 驅動的實測平台。</p>
<p>根據 Phoronix 報導，針對 Linux 7.4 merge window 的 Direct Rendering Manager（DRM）Rust 變更已上載至 DRM-Next 供整合，在該開發週期正式開始之前先行提交。Nova 是 NVIDIA 為其新一代 GPU 開發的 in-kernel Rust 驅動，持續引領 kernel 內 Rust GPU 驅動的發展，與此同時亦不斷完善共用的 Rust DRM 基礎設施——日後其他硬件供應商都將倚賴這套基礎。</p>
<p><strong>不只是一家供應商的項目</strong></p>
<p>Nova 並不單純是 NVIDIA 的項目。由於它是 DRM 子系統中最先進的 Rust 驅動，其開發實際上同時資助了框架本身的研究與設計工作——包括讓任何供應商都能以 Rust 而非 C 編寫 GPU 驅動的抽象層、traits 及相關架構。日後開發的其他驅動將直接沿用大量這類基礎工作，無需從零開始。以 open source 的標準而言，Nova 就是 reference implementation。</p>
<p>另一個重要原因是記憶體安全。kernel 社群更廣泛地推動以 Rust 重寫效能關鍵子系統，本質上是關於結構性風險的討論。圖形堆疊中歷史悠久的 C 代碼一直是記憶體損毀（memory corruption）bug 的溫床。以 Rust 編寫的驅動，可將整類此類 bug 從「有可能發生」轉變為「大部分已被 compiler 阻止」——對於大規模運行這些驅動的人員而言，這是意義重大的改進。</p>
<p><strong>Firmware offload，從頭構建</strong></p>
<p>Nova 的架構本身亦值得了解。與現有 open source Nouveau 驅動的較新代碼路徑相似，Nova 依賴 NVIDIA 的 GSP（GPU System Processor）firmware：將驅動的大量複雜運算 offload 到 GPU 本身運行的 firmware，而非在 kernel 中複製未公開的硬件行為。不同之處在於，Nova 一開始便是以 Rust 編寫，而 Nouveau 則是歷史悠久的 C codebase，後來才加以改造以使用 GSP。Nova 的開發很大程度上由公司 open kernel 圖形團隊的工程師主導。</p>
<p>值得注意的是，無論 Nouveau 還是 Nova，都未能在許多生產工作負載中取代 NVIDIA 的 proprietary 驅動；proprietary 堆疊仍然是高要求部署的實際參考標準。Nova 的意義在於，它是首次在現代 NVIDIA 硬件上公開縮窄這段差距。</p>
<p><strong>圖形堆疊的構成為何重要</strong></p>
<p>對於香港快速擴張的 AI 及 GPU 密集型數據中心建設而言，Linux 圖形堆疊的構成絕非桌面層面的問題。數據中心營運商在 proprietary 與 open kernel 元件之間選擇時，會在供應鏈透明度、可審計性及長期可維護性，與首日效能之間作出取捨。一個記憶體安全、由 upstream 維護的驅動，為廣泛部署的 GPU 提供了一個前所未有的可信 open source 選擇——尤其是在亞洲各地的 AI 等 GPU 密集型部署中，伺服器規模龐大，每一個驅動的可靠性都會迅速產生複合效應。</p>
<p>Linux 7.4 merge window 預計即將開啟，屆時這些變更將開始其在 mainline review 流程中的旅程。若 Nova 再次主導該週期的 Rust 工作，將進一步印證近幾個版本以來日漸清晰的模式：長期以來被視為 open source 圖形故事中反派的 NVIDIA，如今正編寫著定義其未來的代碼。</p>
