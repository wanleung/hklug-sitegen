<p>According to Phoronix's coverage, another operating system has reportedly been "coded from scratch" with heavy help from AI agents — and this one arrives with a twist: NULLos ships closed-source, a decision its proponents frame as a security measure rather than a commercial one.</p>
<p>Phoronix's reporting, based on a submission to its inbox, places NULLos in what it describes as a steady flow of LLM-assisted operating system announcements — now routine enough that the publication treats each new arrival as one entry in a flood. Most of those projects, Phoronix notes, at least publish their source code. NULLos does not, and its stated rationale is that withholding the code leaves attackers with less to study.</p>
<p>That framing is the crux of the story, and it is why the project matters beyond its own feature list.</p>
<h4>The contradiction</h4>
<p>The pitch: an operating system assembled largely by AI agents, kept closed so that attackers cannot read it. The reasoning inverts a decades-old consensus in systems security — that open scrutiny finds flaws, and that hiding code merely hides flaws from defenders while leaving them intact for anyone who bothers to reverse-engineer a binary.</p>
<p>The tension is sharper because the code is machine-generated in the first place. The failure modes most commonly reported in LLM-written code fall in exactly the areas an OS kernel cannot afford them: vulnerabilities inherited from training data, hallucinated API signatures, and subtle concurrency and memory-safety errors. Those are the defects external review is best positioned to catch — and NULLos's posture forecloses that review by design.</p>
<p>In effect, the project asks users to accept a double substitution: trust the model's output instead of a human engineer's, and trust the vendor's assurances instead of an independent auditor's. When code is cheap to generate, verification becomes the scarce resource. NULLos cannot be inspected, forked, or patched by outsiders; it can only be believed.</p>
<p>That is the real news value here, and it is likely why Phoronix highlighted the closed-source decision rather than the technical specification sheet. Each weekly AI-built OS is a small referendum on how much confidence the community is willing to place in generated code — and NULLos tests the outer limit of that willingness.</p>
<h4>Why it matters to the wider community</h4>
<p>For open-source practitioners, the project is a useful foil. It makes concrete an argument that usually stays abstract: that "open" is not merely a licensing label but an auditability guarantee. A closed, AI-authored system offers neither legibility nor reproducibility, so its security rests entirely on claims that outsiders cannot check.</p>
<p>The same question reaches enterprise buyers who must decide, on record, what evidence they require before adopting new infrastructure — and whether "built with AI" raises or lowers their confidence in a vendor's security posture. That is a trust-and-governance question, not a licensing debate, and it will recur as more AI-authored components appear in procurement shortlists.</p>
<p>Phoronix's tone is characteristically sceptical — its framing treats NULLos as one entry in a flood rather than a breakthrough — and the appropriate posture for most readers is to watch rather than deploy. The project may still be legitimate, but its own chosen disclosure posture means readers cannot independently verify that for themselves.</p>

<p>據 Phoronix 報道，另一個作業系統據稱「由零開始編寫」，並大量借助 AI agent 完成——而這個系統登場時帶有一個特點：NULLos 以閉源形式發行，其支持者將此舉定性為保安措施，而非商業決定。</p>
<p>Phoronix 根據投寄至其收件箱的一篇投稿作出報道，將 NULLos 歸入它所形容的 LLM 協助開發作業系統發布消息的持續洪流之中——如今這些消息已成為平常事，該媒體把每個新系統的出現都視為洪流中的一篇條目。Phoronix 指出，此類專案大多至少會公開其原始碼，NULLos 卻沒有這樣做，其公開的理由是：不公開代碼，攻擊者可供研究的材料便會更少。</p>
<p>這種說法正是整篇報道的核心，也是該專案意義超越其本身功能清單的原因。</p>
<h4>矛盾之處</h4>
<p>其賣點是：一個主要由 AI agent 組裝、刻意保持閉源以免攻擊者閱讀的作業系統。這種推理顛覆了系統保安領域數十年來的共識——即公開審視才能找出缺陷，而隱藏代碼只會讓防禦者無從察覺缺陷，但對任何願意逆向工程二進位檔案的人來說，缺陷依然存在。</p>
<p>當中的張力更為尖銳，因為代碼本來就是機器生成的。LLM 編寫代碼最常見的失效模式，恰恰落在作業系統核心最承受不起的範疇：源自訓練資料的漏洞、虛構的 API 簽名，以及微妙的並行與記憶體安全錯誤。這些正是外部審查最能有效捕捉的缺陷——而 NULLos 的立場從設計上便排除了這種審查。</p>
<p>實際上，該專案要求用戶接受雙重替代：信任模型的輸出而非人類工程師的判斷，信任廠商的保證而非獨立審計員的核實。當生成代碼成本低廉時，驗證反而成為稀缺資源。NULLos 無法供外界檢視、fork 或打補丁；它只能被相信。</p>
<p>這才是真正的新聞價值所在，也可能是 Phoronix 特別突出其閉源決定而非技術規格表的原因。每個由 AI 開發的作業系統，都是社群對生成代碼究竟願意給予多少信心的一次小型公投——而 NULLos 測試的正是這份意願的極限。</p>
<h4>對廣泛社群為何重要</h4>
<p>對開源從業者而言，該專案是一個有用的對照案例。它把一個通常停留於抽象層面的論點具體化：「開放」不單是授權標籤，更是一項可審計性的保證。一個閉源、由 AI 撰寫的系統既不具可讀性，也不具可重現性，因此其保安完全依賴外界無法核實的說法。</p>
<p>同一個問題也延伸至企業買家：他們必須留下正式記錄，說明採用新基礎設施前要求什麼證據——以及「以 AI 開發」這一點會提升還是降低他們對廠商保安水平的信心。這是信任與管治的問題，而非授權條款的爭論，而且隨着越來越多由 AI 撰寫的元件進入採購候選名單，這個問題將反覆出現。</p>
<p>Phoronix 的語調一貫帶有審慎懷疑——其行文將 NULLos 視為洪流中的一篇條目，而非突破性進展——對大多數讀者而言，適當的態度是觀望而非部署。該專案或許並非虛構，但它自己選擇的披露立場，令讀者無法獨立核實這一點。</p>
