Title: COSMIC Epoch 1.11 Adds Wayland xdg-dialog-v1 Support and Reworks Multi-GPU Output Handling
Content:
<p>System76 has released COSMIC Epoch 1.11, the latest point release of its Rust-based open-source desktop environment. The update centres on two changes: support for the Wayland <code>xdg-dialog-v1</code> protocol, and a rework of multi-GPU handling logic. According to Phoronix, both changes land in what is nominally a minor release, yet each bears directly on everyday desktop behaviour.</p>
<h4><code>xdg-dialog-v1</code>: closing Wayland's dialog semantics gap</h4>
<p>File dialogs, confirmation boxes and similar interface elements have long lacked a unified protocol under Wayland. The dialog behaviours that X11 handled through window manager hints need a different mechanism in Wayland's compositor-based architecture. <code>xdg-dialog-v1</code> was proposed to fill exactly that gap: it lets an application tell the compositor that a given window is a transient dialog, so it receives the correct focus handling, centring and modal behaviour.</p>
<p>COSMIC Epoch 1.11 has adopted the protocol. For developers, the practical upshot is this: when the COSMIC desktop runs alongside native Wayland toolkits that also implement <code>xdg-dialog-v1</code>, dialogs should behave as expected — sitting correctly above their parent window and taking focus on launch. One caveat applies: the protocol remains at the proposal stage, and desktop-side implementation is only half the chain. Actual results depend on how quickly individual toolkits and applications follow through, so early adopters should read this as a directional signal rather than a complete solution available today.</p>
<h4>Multi-GPU rework: addressing hybrid-graphics pain points</h4>
<p>The second headline change is a rewrite of multi-GPU handling, covering the display output path in full. For anyone running hybrid-graphics hardware — a laptop or workstation combining an integrated GPU with a discrete one — choosing display outputs, switching GPUs and designating rendering devices has historically been among the more error-prone areas of a Wayland desktop. COSMIC's reworked logic should make external-monitor output and rendering-device configuration behave more consistently in dual-GPU setups.</p>
<h4>Practical considerations before you adopt</h4>
<p>What makes these two changes worth watching is that they target the two questions most often raised when assessing Wayland for production use: whether dialogs behave correctly, and whether dual-GPU environments are stable. If your daily work involves external monitors, multi-screen output or GPU-related testing — including for teams and developers evaluating COSMIC from Hong Kong and elsewhere in the region — this round of improvements merits hands-on verification in a test environment.</p>
<p>Two practical considerations are worth keeping in mind before any deployment decision. First, System76 develops COSMIC against hardware it sells itself, so validation results on its own machines may not generalise directly to other vendors' hybrid-graphics equipment — real-world behaviour elsewhere still depends on each machine's drivers and firmware settings. Second, where COSMIC is installed outside Pop!_OS via community packaging, packaging maturity may vary across distributions; check the packaged version and update cadence before relying on it in production.</p>

<p>System76 發布 COSMIC Epoch 1.11，這是其以 Rust 編寫的開源桌面環境的最新小版本更新（point release）。本次更新集中於兩項改動：新增 Wayland <code>xdg-dialog-v1</code> 協議支援，以及重整 multi-GPU 處理邏輯。據 Phoronix 報導，兩項改動雖然落在一個名義上的小版本之內，但每一項都直接影響日常桌面操作行為。</p>
<h4><code>xdg-dialog-v1</code>：填補 Wayland 對話框語義的缺口</h4>
<p>File dialog、確認框等介面元素，在 Wayland 下長期以來缺乏統一的協議規範。X11 透過 window manager hints 處理的對話框行為，在 Wayland 以 compositor 為基礎的架構下需要另一套機制。<code>xdg-dialog-v1</code> 正是為填補這項缺口而提出：它讓應用程式能通知 compositor 某個視窗屬於 transient dialog，從而獲得正確的焦點處理、置中顯示與模態行為。</p>
<p>COSMIC Epoch 1.11 已採用該協議。對開發者而言，最實際的影響是：當 COSMIC 桌面與同樣實作 <code>xdg-dialog-v1</code> 的原生 Wayland toolkits 協同運作時，對話框應能如預期般運作——正確置於父視窗之上，並在啟動時取得焦點。但有一點需要留意：該協議目前仍處於 proposal 階段，桌面端的實作只是鏈條的一半。實際效果取決於各 toolkit 與應用程式的跟進速度，因此早期採用者應將其視為一個方向性訊號，而非即時可用的完整解方。</p>
<h4>Multi-GPU 重整：處理 hybrid-graphics 痛點</h4>
<p>第二項重點改動是 multi-GPU 處理的全面重寫，涵蓋整個顯示輸出路徑。對使用 hybrid-graphics 硬件的使用者——即配備整合 GPU 加獨立 GPU 的筆記型電腦或工作站——而言，選擇顯示輸出、切換 GPU 以及指定渲染裝置，向來是 Wayland 桌面上較易出錯的環節。COSMIC 重整後的邏輯，應能令外接顯示器輸出與渲染裝置配置在雙 GPU 設定下運作更一致。</p>
<h4>採用前的實際考慮</h4>
<p>這兩項改動值得關注之處，在於它們正好針對評估 Wayland 用於正式環境時最常被提出的兩個問題：對話框行為是否正確，以及雙 GPU 環境是否穩定。若你的日常工作涉及外接顯示器、多螢幕輸出或 GPU 相關測試——包括來自香港及區內其他地方、正評估 COSMIC 的團隊與開發者——本次改進值得在測試環境中實際驗證。</p>
<p>在作任何部署決定前，有兩點實際考慮值得留意。其一，System76 是針對自家銷售的硬件開發 COSMIC，因此在其自有機器上取得的驗證結果，未必能直接推論到其他廠商的 hybrid-graphics 設備——在其他平台上的實際表現，仍取決於各台機器的驅動程式與韌體設定。其二，若透過社群封裝在 Pop!_OS 以外安裝 COSMIC，各發行版的打包成熟度可能不一；在正式環境倚賴之前，宜先確認封裝版本與更新節奏。</p>
