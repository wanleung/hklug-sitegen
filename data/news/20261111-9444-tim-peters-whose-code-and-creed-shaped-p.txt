Title: Tim Peters, whose code and creed shaped Python, dies
Content:
<p>```</p>
<p>The Python community is mourning Tim Peters, the contributor best known for two very different things: the sorting algorithm that carries his name and the set of aphorisms known as the Zen of Python. Guido van Rossum, Python's creator, conveyed the news of Peters's passing in a memorial post, and LWN.net published a remembrance headlined "In Memoriam: Tim Peters 1952–2026."</p>
<p>The announcement arrived some time after Peters died — van Rossum himself described the news as "somewhat delayed" — so this is a remembrance rather than a breaking-news story, with further tributes expected as the community absorbs it.</p>
<p>Van Rossum framed Peters's contribution in personal terms. "It's hard to overestimate Tim's influence on Python," he wrote. "He's probably best known for writing the Zen of Python (PEP 20), but to me he was a mentor and language co-designer long before that." Van Rossum added that Peters found Python not long after its initial release.</p>
<p><strong>Two legacies: an algorithm and a doctrine</strong></p>
<p>Beyond the Zen, Peters's fingerprints are on the language at a concrete level. In his memorial post, van Rossum recounts how Peters convinced him to support mixed int/float arithmetic — a decision that shapes everyday Python code every time an integer and a float are added together. It is the kind of quiet, foundational argument that rarely makes release notes but changes how a language feels to use.</p>
<p>Peters is also widely credited with Timsort, the stable, adaptive sorting routine that became CPython's default sort — as documented in the <a href="https://devguide.python.org/">Python developer's guide</a> and the algorithm's own technical write-ups — and has since been taken up, in variant form, by other language ecosystems. It is a rare case of a developer's name becoming shorthand for a piece of code many work with daily.</p>
<p>His other legacy is quieter but arguably more durable: PEP 20, the Zen of Python. The aphorisms codified there — from "Beautiful is better than ugly" to "Namespaces are one honking great idea — let's do more of those!" — have served as design doctrine for the language for more than two decades, shaping how core developers weigh trade-offs in proposals and how the wider community talks about Pythonic code. PEP 20 is unusual among Python's governance documents in that it prescribes no process; it is a statement of values, and it has outlived many concrete features debated since.</p>
<p><strong>Why it matters beyond the obituary</strong></p>
<p>For working engineers, Peters's career illustrates two routes to influence in open source: shipping foundational code that outlasts any single release, and articulating principles that outlast any single implementation. Both are visible in everyday work — a sort call that quietly does the right thing on nearly sorted data, and a style debate settled by quoting a line from PEP 20.</p>
<p>Because the news reached the community late, Peters's remembrance is still taking shape; van Rossum's original post and the full LWN.net piece remain the primary accounts.</p>

<p>Python 社群正悼念 Tim Peters，這位貢獻者以兩件截然不同的事蹟為人熟知：以他命名的排序算法，以及一組名為《Python 之禪》的格言。Python 創始人 Guido van Rossum 在一篇悼念文章中轉達了 Peters 離世的消息，LWN.net 則刊出標題為「In Memoriam: Tim Peters 1952–2026」的悼文。</p>
<p>消息在 Peters 去世後一段時間才傳出——van Rossum 本人形容消息「稍有延遲」——因此這是一篇悼念報導而非突發新聞，隨著社群逐步消化此事，預期仍會有更多悼念表述。</p>
<p>Van Rossum 以個人角度闡述 Peters 的貢獻。他寫道：「Tim 對 Python 的影響再怎麼強調也不為過。他最廣為人知的或許是撰寫《Python 之禪》（PEP 20），但對我而言，他在那之前早已是我的導師及語言共同設計者。」Van Rossum 補充，Peters 在 Python 初版發布後不久便接觸並投入其中。</p>
<p><strong>兩份遺產：一套算法與一套信條</strong></p>
<p>在《之禪》之外，Peters 的印記亦體現在語言的具體層面。Van Rossum 在悼念文章中憶述，Peters 如何說服他支持 int／float 混合算術運算——這項決定令整數與浮點數每一次相加時，都影響了日常 Python 代碼的運作。這正是那種低調卻根基深厚的論證，鮮少見於版本發行說明，卻改變了一門語言的使用感受。</p>
<p>外界普遍將 Timsort 歸功於 Peters——這套穩定、自適應的排序例程成為 CPython 的預設排序方式，此點已載於 <a href="https://devguide.python.org/">Python 開發者指南</a>及該算法本身的技術說明之中；此後其變體亦獲其他語言生態系統採用。這是一個鮮見的例子：開發者的名字成為一段許多人每日接觸的代碼的代稱。</p>
<p>他的另一份遺產較為低調，但或許更為長久：PEP 20，《Python 之禪》。當中載明的格言——從「優美勝於醜陋」到「命名空間是絕妙的主意——我們應該多做這樣的東西！」——二十多年來一直是該語言的設計信條，塑造核心開發者如何在提案中權衡取捨，以及廣大社群如何談論 Pythonic 代碼。PEP 20 在 Python 的治理文件中別樹一幟，並未規定任何流程；它是一份價值觀聲明，且比其後許多備受爭議的具體功能更為長壽。</p>
<p><strong>為何這不止是一則訃告</strong></p>
<p>對在職工程師而言，Peters 的職業生涯展示了在開源世界取得影響力的兩條路徑：推出能超越任何單一版本的根基性代碼，以及闡述能超越任何單一實現的原則。兩者在日常工作皆清晰可見——一次排序呼叫在近乎有序的數據上悄然做出正確處理，以及一場風格之爭以引用 PEP 20 的一句話作結。</p>
<p>由於消息較遲才傳至社群，對 Peters 的悼念仍在成形之中；van Rossum 的原文及 LWN.net 全文仍是主要的報導依據。</p>
