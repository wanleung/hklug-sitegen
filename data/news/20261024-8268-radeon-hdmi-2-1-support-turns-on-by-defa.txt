Title: Radeon HDMI 2.1 Support Turns On by Default in Linux 7.4 DRM Pull
Content:
<p>Users running AMD Radeon graphics cards on Linux may soon be able to plug a high-refresh-rate or high-resolution HDMI display into their machine and have it work without tweaking kernel parameters or reaching for a DisplayPort cable — thanks to a change in the latest Direct Rendering Manager (DRM) driver batch.</p>
<p>According to Phoronix, the full set of DRM driver updates for Linux 7.4 merged overnight, bringing a wide range of graphics and display improvements across the kernel's open-source driver stack. The headline change, Phoronix reports, is in the AMDGPU driver: HDMI 2.1 Fixed Rate Link (FRL) is now enabled by default, alongside other HDMI 2.1 features.</p>
<h4>Why FRL matters at the desk</h4>
<p>HDMI 2.1's FRL encoding replaces the older TMDS signalling used by previous HDMI generations, and it is what unlocks the standard's 48Gbps-class bandwidth — the headroom needed for output configurations such as 4K above 60Hz and 8K-class video. Historically, enabling FRL on AMD hardware under Linux has involved manual configuration or workarounds, with DisplayPort often serving as the more friction-free connection for enthusiast monitors.</p>
<p>Enabling FRL by default removes that friction. For a workstation or desk setup built around HDMI — a common scenario with televisions used as monitors, docks, and AV receivers in the signal path — the practical result is that high-bandwidth HDMI output should work out of the box once the updated kernel ships, rather than requiring users to discover and set the right options themselves.</p>
<p>That out-of-the-box reliability matters more broadly for display setups that mix connection types. Any time a display path needs manual intervention, it raises the bar for less experienced users and adds a troubleshooting variable for IT staff provisioning Linux desktops. Phoronix notes that the pull also includes other HDMI 2.1 features, though it does not itemise them.</p>
<h4>Availability</h4>
<p>As with any merge-window content, timing is the next question. The changes are part of the DRM pull that Phoronix reports was merged for Linux 7.4, meaning they would first reach users through the release candidate cycle before arriving in a final release — and, later, in the distribution kernels that downstream projects such as Ubuntu, Fedora, and Debian carry.</p>
<p>The main thing the community will be watching during that RC cycle is whether FRL-by-default holds up reliably across the range of docks, televisions, and AV receivers people actually connect to — the connector and dock combinations where defaults have historically needed adjustment.</p>
<p>Operators who need the change in production will likely want to wait for a distribution-supported kernel rather than running release candidates, but the enablement appears set to become a standard part of the AMDGPU driver rather than an opt-in experiment.</p>
<h4>Context</h4>
<p>The change is also a useful reminder of how much of the modern Linux desktop experience is decided in the DRM subsystem: connector handling, link training, and encoding defaults are rarely visible to users when they work — and immediately noticeable when they do not. Decisions made in this layer ripple outward to every downstream kernel that ships the driver.</p>
<p>AMD users tracking the change, along with IT professionals evaluating Linux desktop deployments, can follow the details on Phoronix, which covered the DRM pull for Linux 7.4.</p>
<hr>
<p>在 Linux 上使用 AMD Radeon 顯卡的用戶，日後或可直接接上高更新率或高解像度的 HDMI 顯示器使用，毋須調整 kernel 參數或改用 DisplayPort 線材——這要歸功於最新一批 Direct Rendering Manager（DRM）驅動的改動。</p>
<p>據 Phoronix 報道，Linux 7.4 的完整 DRM 驅動更新批次已於昨夜合併，為 kernel 的開源驅動堆疊帶來一系列圖形及顯示方面的改進。Phoronix 指出，最矚目的改動在於 AMDGPU 驅動：HDMI 2.1 Fixed Rate Link（FRL）現已預設啟用，同時啟用的還有其他 HDMI 2.1 功能。</p>
<h4>為何 FRL 對桌面應用重要</h4>
<p>HDMI 2.1 的 FRL 編碼取代了舊有 HDMI 版本所採用的 TMDS 信號方式，正好讓該標準得以提供 48Gbps 級別的頻寬——即輸出 4K 60Hz 以上及 8K 級別影片等配置所需的餘裕。過往在 Linux 下的 AMD 硬件啟用 FRL，一直需要手動配置或採用權宜方法，因此對於發燒級顯示器而言，DisplayPort 往往是更少障礙的連接選擇。</p>
<p>預設啟用 FRL 有助消除這方面的障礙。對於以 HDMI 為核心的工作站或桌面配置——包括以電視充當顯示器、連接 dock 以及訊號路徑中的 AV 擴音機等常見場景——實際效果是：只要更新後的 kernel 正式推出，高頻寬 HDMI 輸出便能開箱即用，毋須用戶自行發掘及設定正確選項。</p>
<p>這類開箱即用的可靠性，對於混合使用不同連接方式的顯示配置尤其重要。只要顯示路徑任何一環需要人工干預，便會提高新手用戶的使用門檻，亦為部署 Linux 桌面的 IT 人員增添一個除錯變數。Phoronix 註明，該次 pull 亦包含其他 HDMI 2.1 功能，惟未有逐一列舉。</p>
<h4>何時可用</h4>
<p>一如任何 merge window 的內容，時機是下一個問題。上述改動屬於 Phoronix 報道已合併至 Linux 7.4 的 DRM pull，意味著用戶會先在 release candidate（RC）測試週期接觸到這些改動，之後才會隨正式版本推出——再往後，則會進入 Ubuntu、Fedora、Debian 等下游項目所維護的發行版 kernel。</p>
<p>在 RC 週期內，社群最關注的將是預設啟用 FRL 是否能在用戶實際使用的各類 dock、電視及 AV 擴音機上穩定運作——特別是那些歷來需要調整預設值的連接器與 dock 組合。</p>
<p>需要在生產環境採用此改動的營運者，一般應等待發行版支援的 kernel，而非運行 release candidate；不過，這項啟用功能看來將成為 AMDGPU 驅動的標準配置，而非需要自行選擇啟用的實驗性功能。</p>
<h4>背景</h4>
<p>這項改動亦提醒我們，現代 Linux 桌面體驗有相當大部分其實取決於 DRM 子系統：connector 處理、link training 及編碼預設值在運作正常時很少引起用戶注意，一旦出問題卻會立刻察覺。這一層面所作的決定，會層層向外影響每一個載有該驅動的下游 kernel。</p>
