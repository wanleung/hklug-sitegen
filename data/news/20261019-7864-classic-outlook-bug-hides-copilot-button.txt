<h3>Classic Outlook bug hides Copilot buttons — Microsoft ships fix</h3>
<p>Microsoft has patched a known issue that made the Copilot Chat and Copilot buttons disappear from the mail interface of the classic (desktop) Outlook client for some Windows users. No licence or subscription changes are required on the customer side.</p>
<h4>What happened</h4>
<p>The problem was isolated to classic Outlook desktop users. Affected users found the Copilot Chat and Copilot buttons missing from the interface, cutting off paying customers from the entry point to Copilot. Microsoft classified it as a known issue and has released a fix.</p>
<p>Worth noting: this was a UI-layer regression, not a Copilot service outage — licences and cloud features remained intact, users simply lost the button to reach them. The coexistence of classic and new Outlook deployments explains why only some users were affected. In enterprise environments, this class of issue is routinely underestimated: the feature isn't broken, but users don't know how to invoke it and end up raising tickets with IT.</p>
<h4>For admins: how to verify the fix is applied</h4>
<p>Microsoft and BleepingComputer have not yet published specific build numbers, KB articles, or release channel details. Admins can verify through the following paths:</p>
<ol>
<li><strong>Microsoft 365 admin center Message Center</strong>: look for announcements matching "classic Outlook" and "Copilot buttons" to confirm the update and applicable build.</li>
<li><strong>Windows Update / Microsoft 365 Apps update channels</strong>: confirm that managed devices are on an update channel aligned with company policy and have downloaded the corresponding update.</li>
<li><strong>Microsoft Learn KB articles</strong>: search by symptom (classic Outlook missing Copilot buttons) to confirm the corresponding KB number for the fix.</li>
</ol>
<h4>HK enterprise IT checklist</h4>
<p>General remediation guidance, not tailored to any specific organisation:</p>
<ul>
<li><strong>Inventory classic Outlook users</strong>: in a Microsoft 365 Apps environment, classic and new Outlook coexist — first confirm which accounts still default to the classic client.</li>
<li><strong>Verify update channels</strong>: if deployments are managed by update channel, confirm affected machines have received the update containing the fix.</li>
<li><strong>Check GPO / Intune settings</strong>: where Group Policy or Intune governs Outlook version switching or update policy, confirm no policy is blocking the fix from applying.</li>
<li><strong>Post-fix spot check</strong>: have a small number of affected users sign out and restart Outlook, confirm the Copilot buttons reappear, then notify broadly.</li>
<li><strong>If buttons are still missing</strong>: first confirm the user's licence actually includes Copilot, then check whether the update has genuinely downloaded and installed rather than merely reporting "you're up to date."</li>
</ul>
<h4>Why this matters</h4>
<p>The incident reflects a broader trend: AI features are now deeply embedded in core enterprise productivity workflows. When the Copilot button disappears, what's lost isn't the "extra value" of a new feature but the everyday entry point users rely on — even with cloud services healthy, a single interface-layer bug is enough to neutralise the enterprise's AI investment.</p>
<p>For Hong Kong enterprises built primarily on Microsoft 365, this class of UI regression is difficult to anticipate, but standardised update management and periodic spot checks can shorten detection time. Adding Copilot button availability to routine health checks is near-zero cost and prevents problems from accumulating until users mass-report them.</p>

<h3>經典版 Outlook 錯誤令 Copilot 按鈕消失　微軟已修復</h3>
<p>微軟已修正一項已知問題（known issue）：部分 Windows 用戶在經典版（desktop）Outlook 的郵件介面中，Copilot Chat 及 Copilot 按鈕會無預警消失。用戶毋須作出任何授權或訂閱上的變動。</p>
<h4>事件概述</h4>
<p>問題集中於經典版 Outlook 桌面用戶。受影響的用戶發現 Copilot Chat 及 Copilot 按鈕從介面消失，令已付費用戶無法透過原有入口使用 Copilot 功能。微軟視之為已知問題，並已推出修復。</p>
<p>值得留意的是，今次屬介面層面的回歸（regression），而非 Copilot 服務本身故障——授權與雲端功能均維持正常，只是用戶失去了進入的按鈕。經典版與新版 Outlook 並存的部署模式，解釋了為何只有部分用戶受影響。在企業環境中，此類問題往往被低估：功能本身並未失效，但使用者不知道如何啟用，最終轉向 IT 部門求助，形成大量內部工單。</p>
<h4>作為管理員　如何確認修復已套用</h4>
<p>微軟及 BleepingComputer 目前未披露具體 build 編號、KB 文件及發佈渠道，管理員可循以下途徑自行核實：</p>
<ol>
<li><strong>Microsoft 365 管理中心 Message Center</strong>：查找與「classic Outlook」及「Copilot buttons」相關的公告，確認修復所屬更新及適用 build。</li>
<li><strong>Windows Update / Microsoft 365 Apps 更新通道</strong>：確認受管理裝置的更新通道符合公司政策，並已下載對應修復。</li>
<li><strong>Microsoft Learn 的 KB 文件</strong>：以問題症狀（經典版 Outlook 缺少 Copilot 按鈕）作關鍵字搜尋，確認修復對應的 KB 編號。</li>
</ol>
<h4>香港企業 IT 部門檢查清單</h4>
<p>以下為一般性排查建議，並非針對特定機構狀況：</p>
<ul>
<li><strong>清點使用經典版 Outlook 的用戶</strong>：在 Microsoft 365 Apps 環境中，經典版與新版 Outlook 並存，需先確認哪些帳戶仍以經典版為預設。</li>
<li><strong>核對更新通道</strong>：若部署以更新通道管理，確認受影響機器已接收含修復的更新。</li>
<li><strong>以 GPO / Intune 驗證設定</strong>：如以群組原則或 Intune 管理 Outlook 版本切換或更新政策，確認政策未有阻擋修復套用。</li>
<li><strong>修復後實機抽查</strong>：讓數名受影響用戶登出並重新啟動 Outlook，確認 Copilot 按鈕已重現，再作大範圍通知。</li>
<li><strong>若按鈕仍缺失</strong>：先確認用戶的授權確實包含 Copilot 功能，再檢查更新是否已實際下載安裝，而非僅顯示「已是最新」。</li>
</ul>
<h4>為何此事值得注意</h4>
<p>今次事件反映一個更廣泛的趨勢：AI 功能已深度嵌入企業的核心生產力流程。當 Copilot 按鈕消失，受影響的不是新功能的「額外價值」，而是用戶日常工作的實際入口——即使雲端服務一切正常，介面層面的一個 bug 就足以令企業對 AI 的投資形同虛設。</p>
<p>對香港以 Microsoft 365 為主力的企業而言，此類介面回歸難以事先防範，但透過標準化更新管理及定期實機抽查，可縮短察覺時間。把 Copilot 按鈕的可用性列入日常健康檢查清單，成本極低，卻可避免問題積累至用戶大規模求助才被發現。</p>
