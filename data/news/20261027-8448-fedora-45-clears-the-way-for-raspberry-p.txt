Title: Fedora 45 clears the way for Raspberry Pi 5B, but two boards are still waiting
Content:
<p>Fedora's next release will run on every variant of the Raspberry Pi 5B — with caveats — while buyers of the Compute Module 5 and the Pi 500+ will need to keep waiting. And Fedora 44 users are not locked out, but are told a temporary workaround is needed at boot.</p>
<p>That is the picture Peter Robinson paints in a blog post, summarised by LWN.net. According to Robinson, the upcoming Fedora 45 release will work on all Raspberry Pi Model 5B variants, subject to caveats; the Compute Module 5 and Pi 500+ remain works in progress. On Fedora 44, he notes a temporary boot-time workaround is required — with the implication that keeping the kernel and firmware updated promptly can make it a one-time step rather than a permanent one.</p>
<p>The gap matters because single-board hardware has consistently shipped faster than mainstream distributions can validate it. For anyone choosing a board around a Linux target rather than the other way around, one release cycle of missing support is the difference between a working project and a stalled one.</p>

<p>The practical split:</p>
<ul>
<li><strong>Pi 5B variants:</strong> the mainstream option. Fedora 45 is the target release; Fedora 44 users are not locked out, but must apply the boot workaround Robinson describes.</li>
<li><strong>Compute Module 5:</strong> the embedded variant used in custom carrier-board and edge deployments. Support is explicitly "work in progress" — not blocked, but not ready.</li>
<li><strong>Pi 500+:</strong> the desktop/education-style variant, same status as the CM5.</li>
</ul>
<h4>Analysis: matching board to release</h4>
<p>The sections below are editorial guidance drawn from the status table above, not further reporting from the source. The guidance is straightforward: <strong>match the board to the release</strong>.</p>
<ul>
<li>If Fedora is the target OS, a <strong>Pi 5B variant</strong> is the board to buy now, planning around Fedora 45.</li>
<li>If the project specifically needs a <strong>CM5</strong> (custom carrier boards, embedded deployments) or a <strong>Pi 500+</strong>, and Fedora is a hard requirement, <strong>hold off</strong> until that board's status changes — or choose an OS where it is already supported.</li>
<li>Teams with <strong>Fedora 44 deployments</strong> should apply the documented workaround now and move to Fedora 45 when it lands rather than relying on the stopgap.</li>
</ul>
<h4>Analysis: before you commit hardware</h4>
<ul>
<li><strong>"With caveats" is not a clean pass.</strong> The specifics sit in Robinson's original post, which should be checked directly before hardware is committed.</li>
<li><strong>Fedora 45 is still upcoming</strong>, so status may shift as launch approaches.</li>
<li><strong>The Fedora 44 workaround is temporary</strong> — do not bake it into long-lived images or provisioning scripts.</li>
<li><strong>CM5 and Pi 500+ users should plan on waiting</strong>; neither board has reached the "works with caveats" stage.</li>
</ul>
<p>Hardware availability consistently outpaces distribution support in ARM Linux, so board selection and OS selection are increasingly a single decision rather than two.</p>

<p>Fedora 下一個版本將可在 Raspberry Pi 5B 的所有變體上運行——但附帶若干限制條件——而 Compute Module 5 及 Pi 500+ 的買家則仍需繼續等待。另一方面，Fedora 44 用戶並未被拒諸門外，但被告知開機時需要採用一個臨時的 workaround。</p>
<p>以上是 Peter Robinson 在一篇網誌文章中描繪的情況，並由 LWN.net 作出摘要。根據 Robinson 的說法，即將推出的 Fedora 45 將可在所有 Raspberry Pi Model 5B 變體上運作，但須受若干限制條件所規限；Compute Module 5 及 Pi 500+ 則仍在開發中。在 Fedora 44 方面，他指出開機時需要一個臨時的 workaround——言下之意是，若及時更新 kernel 與 firmware，該步驟可僅需執行一次，而非永久性質。</p>
<p>這個落差並非小事，因為單板硬件的推出速度向來快於主流發行版對其進行驗證的速度。對於那些圍繞 Linux 目標而非倒過來挑選開發板的人來說，缺少支援的一個 release cycle，足以令一個順利運作的項目與一個停滯不前的項目產生天淵之別。</p>

<h4>分析：按版本選板</h4>
<p>以下各節屬編輯分析，取材自上方狀態表，並非來自消息來源的進一步報道。指引十分直接：<strong>按版本選板</strong>。</p>
<ul>
<li>如果 Fedora 是目標作業系統，現階段應購買 <strong>Pi 5B 變體</strong>，並以 Fedora 45 為規劃基礎。</li>
<li>如果項目確實需要 <strong>CM5</strong>（自訂 carrier board、嵌入式部署）或 <strong>Pi 500+</strong>，而 Fedora 又是硬性要求，<strong>宜暫緩購買</strong>，直至該開發板的狀態改變——或者改用已支援該板的作業系統。</li>
<li>持有 <strong>Fedora 44 部署</strong>的團隊，應立即套用文中所述的 workaround，待 Fedora 45 正式推出後便行升級，而非長期依賴這個權宜之計。</li>
</ul>
<h4>分析：購入硬件之前須知</h4>
<ul>
<li><strong>「附帶限制條件」並非毫無問題的通過。</strong>具體細節載於 Robinson 的原文，落實購買硬件前應直接查閱。</li>
<li><strong>Fedora 45 尚未正式推出</strong>，因此狀態可能隨發佈日期臨近而有所變動。</li>
<li><strong>Fedora 44 的 workaround 屬臨時性質</strong>——切勿將其嵌入長期使用的 image 或 provisioning 腳本之中。</li>
<li><strong>CM5 及 Pi 500+ 用戶應做好等待的準備</strong>；兩款開發板均未達至「可運作但附帶限制條件」的階段。</li>
</ul>
<p>在 ARM Linux 生態中，硬件供應向來先行於發行版支援，因此選擇開發板與選擇作業系統，已日益成為一個不可分割的整體決定，而非兩個獨立決定。</p>
