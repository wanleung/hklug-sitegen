Title: Self-Hosted Nextcloud Operators Urged to Audit Optional Collabora Add-On After Web Shell Campaign
Content:
<p><strong>TL;DR for HK self-hosters:</strong> If you run Nextcloud on a single VPS or an on-prem box, check whether the optional <strong>Collabora Online – Built-in CODE Server</strong> app is installed, and check it <em>today</em>. Attackers have been planting web shells on Nextcloud servers by going through that add-on, according to a report by The Hacker News. If you never installed the CODE app, you are not exposed to this particular attack path — but it is still worth confirming rather than assuming.</p>
<h4>What happened</h4>
<p>As reported by The Hacker News, attackers exploited a flaw in the optional Nextcloud app "Collabora Online – Built-in CODE Server" to plant web shells on Nextcloud servers. Three administrators have publicly reported compromises via GitHub, with the earliest logged attack dated 10 September. A web shell is a small file that lets an attacker issue arbitrary commands through a web request, executed with the privileges of the web server account — typically <code>www-data</code> or the equivalent nginx/php-fpm user. From there, an intruder can read and modify files, pivot to other services on the same host, or establish persistence.</p>
<p>The compromise is not theoretical: three independent administrators have described it, which is enough to treat this as an active, live threat rather than a lab finding.</p>

<h4>Why it matters here in Hong Kong</h4>
<p><em>The following section is editorial background and general guidance from the HKLUG Team — it does not come from the cited report. Nothing in The Hacker News write-up specifically addresses Hong Kong deployments, PDPO obligations, or local deployment patterns; treat the points below as general context for operators here, not as facts drawn from the incident reporting.</em></p>
<p>A large number of local SMEs, schools, NGOs and one-person IT shops run Nextcloud on a single VPS or a NAS in a local data centre, often with a single administrator wearing every hat. That architecture means a web shell is not a contained incident — it is host compromise. It also means the data sitting behind it is very often personal data.</p>
<p>Under the <strong>Personal Data (Privacy) Ordinance (PDPO)</strong>, organisations handling Hong Kong personal data have obligations around data security and, in practice, must be able to account for a breach. A web shell on a Nextcloud instance typically exposes user records, file shares, calendar and contact data, and — because Nextcloud integrations often hold app passwords — potentially the credentials of connected services. Data residency matters too: if your Nextcloud instance is your chosen on-shore or in-HK storage layer specifically to keep data close, an intrusion quietly defeats that decision. Assess the incident against your data breach notification and documentation obligations, and involve your DPO or the responsible partner early — not after you have finished cleanup.</p>
<p>This is general guidance only, not legal advice; consult your own DPO or privacy counsel on whether and how the PDPO's breach-handling expectations apply to your specific deployment.</p>
<h4>Check-your-stack checklist</h4>
<ol>
<li><strong>Check whether the Collabora Online – Built-in CODE Server app is enabled.</strong> Visit <em>Settings → Administration → Apps</em> (or query <code>occ app:list</code>). If it is not installed, you are not exposed to this attack path.</li>
<li><strong>Update or disable.</strong> Apply the vendor-patched CODE build, or disable and remove the app if you do not need built-in office editing.</li>
<li><strong>Hunt for web shells.</strong> Look for unexpected <code>.php</code> files under your Nextcloud web root, recently modified files, and unfamiliar endpoints. Check web server access logs for POST requests to odd paths.</li>
<li><strong>Check persistence.</strong> Review crontab (<code>crontab -l</code> for all users, plus <code>/etc/cron.d</code>), systemd user and system units, and <code>authorized_keys</code> under every account including your Nextcloud service account.</li>
<li><strong>Rotate secrets.</strong> Nextcloud admin and user passwords, database credentials, SSL private keys, and any app passwords stored in Nextcloud.</li>
<li><strong>Rebuild, don't just clean.</strong> If you find a web shell, assume the host is owned. Restore from your pre-10 September backup onto fresh infrastructure rather than patching over a compromised box.</li>
</ol>
<p>Check your stack tonight — the earliest confirmed attack is already over a month old.</p>

<h4>事件經過</h4>
<p>據 The Hacker News 報道，黑客利用可選 Nextcloud 應用程式「Collabora Online – Built-in CODE Server」的漏洞，在 Nextcloud 伺服器植入 web shell。已有三名管理員透過 GitHub 公開報告遭入侵，最早一宗有記錄的攻擊日期為 9 月 10 日。Web shell 是一個小型檔案，讓攻擊者透過 web request 發出任意指令，並以 web server 帳戶的權限執行——通常是 <code>www-data</code> 或相應的 nginx/php-fpm 用戶。入侵者由此可以讀取及修改檔案、橫向移動至同一主機上的其他服務，或建立持久化後門。</p>
<p>今次入侵並非純屬理論風險：三名獨立管理員已分別描述遭遇，足以將此事視為正在發生的活躍威脅，而非僅是實驗室發現。</p>

<h4>為何香港用戶需特別留意</h4>
<p><em>以下內容為 HKLUG Team 的編輯背景資料及一般性指引——並非引述自上述報道。The Hacker News 的文章並無特別提及香港的部署情況、PDPO 責任或本地部署模式；以下各點僅供本地用戶作一般背景參考，不應視為源自事件報道的事實。</em></p>
<p>大量本地中小企、學校、非牟利機構及一人 IT 公司，都在本地數據中心的單一 VPS 或 NAS 上運行 Nextcloud，往往只有一名管理員身兼數職。此架構下，web shell 並非一宗可控範圍內的事故，而是整台主機遭淪陷。同時，背後的數據通常正是個人數據。</p>
<p>根據**《個人資料（私隱）條例》（PDPO）**，處理香港個人資料的機構在資料保安方面負有責任，實際上必須能夠就資料外洩作出交代。Nextcloud 實例上的 web shell 通常會暴露用戶紀錄、檔案共享、日曆及聯絡人數據，而且——由於 Nextcloud 整合功能經常儲存 app passwords——有機會連帶洩露已連接服務的認證憑證。數據所在地同樣重要：如果你特意選擇 Nextcloud 作為本地或香港境內的儲存層以確保數據就近保存，一次入侵便會悄然令這個決定失效。請按照資料外洩通知及文件存檔方面的責任評估今次事件，並盡早聯繫你的 DPO 或負責合夥人——而非在完成清理工作之後才行動。</p>
<p>以上僅為一般指引，並非法律意見；如有疑問，請就 PDPO 的資料外洩處理規定如何適用於你的具體部署，諮詢你自己的 DPO 或私隱法律顧問。</p>
<h4>技術架構檢查清單</h4>
<ol>
<li><strong>檢查 Collabora Online – Built-in CODE Server 應用程式是否已啟用。</strong> 前往 <em>Settings → Administration → Apps</em>（或執行 <code>occ app:list</code> 查詢）。如未安裝，你便不受此攻擊路徑影響。</li>
<li><strong>更新或停用。</strong> 套用廠商已修復的 CODE 版本；若不需要內建文書編輯功能，則停用並移除該應用程式。</li>
<li><strong>搜尋 web shell。</strong> 檢查 Nextcloud web root 下有無預期之外的 <code>.php</code> 檔案、最近被修改的檔案，以及不熟悉的 endpoints。查閱 web server access log，留意對可疑路徑的 POST request。</li>
<li><strong>檢查持久化機制。</strong> 審視 crontab（所有用戶執行 <code>crontab -l</code>，另加 <code>/etc/cron.d</code>）、systemd 用戶及系統 units，以及所有帳戶（包括 Nextcloud 服務帳戶）下的 <code>authorized_keys</code>。</li>
<li><strong>更換所有機密。</strong> Nextcloud 管理員及用戶密碼、數據庫認證資料、SSL private keys，以及儲存在 Nextcloud 中的任何 app passwords。</li>
<li><strong>重建而非僅僅清理。</strong> 如發現 web shell，應假設主機已完全失陷。請從 9 月 10 日之前的備份還原至全新基礎設施，而非僅在已受入侵的主機上修補了事。</li>
</ol>
<p>即時檢查你的部署——最早確認的攻擊已發生超過一個月。</p>
