<h3>Plasma 6.8 Drops X11 Support, Catching Some Fedora Users Off Guard After Upgrade</h3>
<p>The KDE Project made it clear back in 2025: <a href="https://kde.org/announcements/plasma/6/6.7.0/">Plasma 6.7</a> would be the final release of the desktop environment to support X11 sessions. Anyone following KDE's announcements knew what was coming when Plasma 6.8 <a href="https://kde.org/announcements/plasma/6/6.8.0/">removed X11 support as promised</a> — but for a number of Fedora KDE Workstation users, the real "surprise" arrived at the moment they sat down to log in.</p>
<p>According to LWN.net, the change caught many Fedora users unaware. Note that the report is marked as paywalled <code>[$]</code> content; this article synthesizes only its public summary along with first-party KDE and Fedora links, rather than reproducing it verbatim.</p>
<h4>The Real Story: Not the Policy, but the Communication Gap</h4>
<p>On the technical policy itself, there was no suspense — KDE's X11 deprecation timeline was published long ago and executed on schedule. The news value lies in the fact that an upstream project's announcement machinery does not necessarily reach users who first encounter the change at the login screen.</p>
<p>What is missing in between is the distribution layer acting as a translator. Fedora sits between KDE's upstream release process and end users, and how — and how early — each distribution relays upstream end-of-life (EOL) decisions to its users remains inconsistent. The problems users hit are usually tied not to any particular region but to upgrade cadence: graphics drivers, multi-monitor behavior, input device handling, and application compatibility are all common friction points in the transition from X11 to Wayland. Whether a platform migration succeeds often depends on migration paths and warning periods, not just on technical maturity.</p>
<p>On this point, Hong Kong Fedora users on rolling or short upgrade cycles follow exactly the same upgrade path as everyone else worldwide — no regional policy variable is in play. In other words, the efficiency of upstream announcement relay is the only variable.</p>
<h4>Wayland Migration Background: Worth Checking Before You Upgrade</h4>
<p>The following is background material compiled by the editorial team and does not come from the LWN report. For KDE users preparing for — or already pushed into — the Wayland era, a few common friction points are worth checking before upgrading: NVIDIA users should install a recent proprietary driver with Wayland support and select "Plasma (Wayland)" at the login screen; for black screens or compositor issues, first check compatibility switches such as <code>KWIN_DRM_NO_AMS</code> and whether kernel mode setting (KMS / modeset) is enabled. Multi-monitor setups should have resolutions, scaling, and workspace layouts re-checked after upgrading, with old <code>xrandr</code> scripts replaced by KDE's settings interface or <code>kscreen-doctor</code>. Remote desktop and screen sharing are constrained by Wayland's security model and must go through the PipeWire-plus-portal path (such as KDE Connect or native Wayland VNC servers), rendering old tools like x11vnc obsolete. As for the XWayland compatibility layer, most X11 applications will still run, though cursor, input method, and font scaling glitches may appear — prefer native Wayland versions of applications when available.</p>
<h4>Lessons for the Open Source Community</h4>
<p>This episode highlights a frequently underestimated agenda item: large desktop projects' deprecation policies need to land at the distribution level — in upgrade notifications, release notes, and installers — before they truly reach users. A change that seems obvious to veteran users who track upstream announcements can be a sudden disruption for users who rely solely on what their distribution pushes out — a communication lesson every open source project should revisit when planning breaking changes.</p>

<h3>Plasma 6.8 移除 X11 支援，部分 Fedora 使用者升級後才察覺</h3>
<p>KDE 專案早在 2025 年就已明確宣告：<a href="https://kde.org/announcements/plasma/6/6.7.0/">Plasma 6.7</a> 將是最後一個支援 X11 工作階段的版本。緊跟 KDE 官方公告的使用者對此早有心理準備，然而對一部分 Fedora KDE 工作站使用者而言，真正的「驚喜」出現在 Plasma 6.8 <a href="https://kde.org/announcements/plasma/6/6.8.0/">如期移除 X11 支援</a>、自己準備登入工作階段的那一刻。</p>
<p>據 LWN.net 報導，這次變動讓不少 Fedora 用戶措手不及。值得注意的是，該篇報導標記為 <code>[$]</code> 付費訂閱內容，本文僅就其公開摘要與一手 KDE、Fedora 連結進行整理轉述，並非逐字引用。</p>
<h4>真正的新聞點：不是政策，而是溝通落差</h4>
<p>就技術政策本身而言，這並沒有任何懸念——KDE 的 X11 棄用時間表早已公布並如期執行。新聞價值在於：上游專案的公告機制，未必能觸及那些只在登入畫面才第一次遇見變更的使用者。</p>
<p>這中間缺少的，正是發行版這一層「轉接器」。Fedora 介於 KDE 的上游發布機制與最終使用者之間，而各發行版如何、以及多早把上游的支援終止（EOL）決定傳遞給使用者，做法至今仍不一致。使用者遭遇的問題通常與特定區域名無關，而是與升級節奏有關：圖形驅動、多螢幕行為、輸入裝置處理與應用程式相容性，都是從 X11 過渡到 Wayland 時常見的摩擦點。平台轉型能否成功，往往取決於遷移路徑與預警期，而不只是技術本身是否成熟。</p>
<p>就這一點而言，跟隨滾動更新或短週期升級的香港 Fedora 使用者，走的是與全球使用者完全相同的升級路徑，並沒有任何地區性的政策介入——換言之，上游公告的傳達效率，就是唯一的變數。</p>
<h4>Wayland 遷移背景：升級前值得留意的幾件事</h4>
<p>以下為編輯部整理的背景資料，並非出自上述 LWN 報導。對準備或已被動進入 Wayland 時代的 KDE 使用者，升級前可先檢查幾個常見摩擦點：NVIDIA 使用者應安裝支援 Wayland 的較新專有驅動，並在登入畫面選擇「Plasma (Wayland)」；若出現黑屏或合成器問題，可先檢查 <code>KWIN_DRM_NO_AMS</code> 等相容性開關，以及核心模式設定（KMS / modeset）是否已啟用；多螢幕配置在升級後應重新確認解析度、縮放與工作區排列，X11 時期的 <code>xrandr</code> 腳本需改由 KDE 設定介面或 <code>kscreen-doctor</code> 取代；遠端桌面與螢幕分享受 Wayland 安全性模型限制，需改走 PipeWire 加 portal 的路徑（如 KDE Connect、Wayland 原生 VNC 伺服器），舊的 x11vnc 類工具將失效；至於 XWayland 相容層，多數 X11 應用仍可執行，但可能出現游標、輸入法與字型縮放的細節異常，遇到問題時優先尋找應用程式的 Wayland 原生版本。</p>
<h4>對開源社群的啟示</h4>
<p>這次事件凸顯一個常被低估的議程：大型桌面專案的棄用政策，需要發行版在升級通知、發行說明與安裝器層級同步落地，才能真正抵達使用者。對習慣自行追蹤上游公告的資深用戶而言理所當然的變動，對只依賴發行版推送的使用者可能是突如其來的中斷——這也是所有開源專案在規劃破壞性變更時，值得反覆檢視的溝通課題。</p>
