Title: AMD Caps Off Linux 7.4 amdgpu Development With Another Batch of HDMI 2.1 Display Fixes
Content:
<p>AMD has sent its final amdgpu pull request to the Linux kernel maintainers ahead of the Linux 7.4 merge window. According to Phoronix, this last round of housekeeping is primarily made up of bug fixes, with the majority targeting HDMI 2.1 output. The patches address a range of issues that have long caused black screens or failure to produce a picture, including 4K@120Hz high-refresh-rate output, variable refresh rate (VRR), and FRL link training — the latest wave in AMD's ongoing effort to shore up HDMI 2.1 support in its display driver.</p>
<p>The pull request itself is just a routine code-submission step; the real question is timing. These patches are expected to enter mainline via the Linux 7.4 merge window, followed by a release candidate testing period. Given the kernel's typical release cadence of roughly two months, it will be several weeks before an official release, after which individual distributions will backport the fixes through their stable branches. In other words, users on Ubuntu LTS, RHEL, Fedora, and other distributions with long-term maintenance branches can expect the fixes through routine kernel updates without having to wait for the next major release — though actual arrival times depend on each distribution's update cadence and backport review process.</p>
<p>Placed in a broader context, AMD's HDMI 2.1 support has never been a one-shot feature drop. It has been an incremental effort spanning multiple kernel releases, with FRL link training, link-rate negotiation, and DSC encoding all requiring repeated fixes. It is precisely for this reason that "another batch of HDMI 2.1 fixes" carries news value in itself: it signals that upstream investment in the amdgpu display stack remains ongoing, rather than indicating that any particular feature is finished.</p>
<p>Not every item made it into 7.4, however. According to AMD, some fixes have been deferred to Linux 7.5. Users experiencing display output problems are advised to check their distribution's kernel update announcements first, and to consider whether a manual kernel upgrade or switching to a newer kernel branch is warranted.</p>

<p>AMD 已向 Linux 核心維護者送出 Linux 7.4 合併視窗前的最後一批 amdgpu 功能 pull request。根據 Phoronix 的報導，這輪「最後一批收尾」以缺陷修正為主，其中多數與 HDMI 2.1 輸出有關，涵蓋 4K@120Hz 高更新率輸出、可變更新率（VRR）以及 FRL 連結訓練等長期以來容易觸發黑屏或無法正常輸出畫面的問題，是 AMD 顯示驅動在 HDMI 2.1 支援上持續補強的最新一波。</p>
<p>pull request 本身只是單純的程式碼提交流程，真正的關鍵在於時程。這批補丁預計隨 Linux 7.4 合併視窗進入主線，之後進入 release candidate 測試期——按 Linux 核心約兩個月的慣常發行節奏，從合併視窗到正式釋出大致需要數週時間——正式釋出後再由各發行版以穩定分支回移的方式套用。換言之，Ubuntu LTS、RHEL 與 Fedora 等採用長期維護分支的使用者，不必等待下一個大版本，就能透過例行的核心更新收到修正；實際到手時間仍取決於各發行版的更新節奏與回移審核。</p>
<p>放在更長的脈絡來看，AMD 的 HDMI 2.1 支援並非一次到位的功能，而是橫跨多個核心版本的漸進工程，包括 FRL 連結訓練、連結速率協商以及 DSC 編碼支援都經歷過反覆修正。正因如此，「又一批 HDMI 2.1 修正」本身就具有新聞價值：它顯示上游對 amdgpu 顯示堆疊的投入仍在持續，而非宣告某項功能已經完工。</p>
<p>本次 pull 也並非所有項目都趕及納入 7.4，按 AMD 說明，部分修正留待 Linux 7.5 再行處理。有顯示輸出困擾的使用者，建議先確認所用發行版的核心更新公告，評估是否需要手動升級核心或改用更新的分支版本。</p>
