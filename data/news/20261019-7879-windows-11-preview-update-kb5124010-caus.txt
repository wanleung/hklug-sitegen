<h3>Windows 11 Preview Update KB5124010 Causes Dolby Digital Apps to Crash, Microsoft Issues Separate Fix</h3>
<p>Microsoft has resolved a flaw introduced by <strong>KB5124010</strong>: after installing the September 2026 Windows 11 preview update, any game or media application relying on <strong>AC-3 (Dolby Digital)</strong> audio decoding crashes immediately. The fix does not come through KB5124010 itself, but through a separate corrective cumulative update delivered via Windows Update; the KB number for that corrective update has not yet been announced.</p>
<h4>First Principle: This Is Not a Security Update</h4>
<p><strong>KB5124010 is a preview update and does not contain any security patches.</strong> Because this defect originates solely from KB5124010, devices that have not installed the update are not exposed to any additional risk and do not need to install KB5124010 retroactively.</p>
<p>In other words, the correct reading of this incident is not "Microsoft has a new supplemental patch that must go live everywhere immediately," but rather dealing with devices that have already crashed — the deployment guidance below is organised along this principle.</p>
<h4>Scope of Impact: AC-3 Decoding Path Fully Affected</h4>
<p>The failure mode is highly concentrated: any application using the AC-3 / Dolby Digital decoding path — including Blu-ray playback, certain console-ported games, and media apps supporting Dolby Digital — crashes immediately once KB5124010 is applied. Because the issue originates from KB5124010, the affected scope is limited to machines that adopted the September preview update.</p>
<p>As for the exact affected build numbers, the report does not enumerate them; deployment should be based on each device's actual build.</p>
<h4>Fix and Delivery Channel</h4>
<p>Microsoft's remedy is a separate corrective cumulative update, released through the normal Windows Update channel. Administrators should check Windows Update for any new cumulative updates available.</p>
<h4>Deployment Guidance (Analysis)</h4>
<p>The following is a deployment reference compiled by this publication based on the report, for IT administrators to evaluate:</p>
<p><strong>1. KB5124010 installed (crashes occurring)</strong>
Apply the corrective cumulative update from Windows Update as soon as possible; if the fix is not yet available, uninstall KB5124010 first and retry in the next scheduled maintenance cycle.</p>
<p><strong>2. KB5124010 not installed (unaffected)</strong>
No action required. Do not proactively adopt this preview update; let the next official security update cycle take its course.</p>
<p><strong>3. Preview update already pushed to production</strong>
First verify the actual build number, re-test AC-3 playback, and only re-certify the deployment after confirming it works; until AC-3 regression testing is complete, these machines should not be marked as compliant.</p>
<h4>Lessons for Patch Management</h4>
<p>This incident once again demonstrates that preview updates and security updates carry fundamentally different risk profiles: the former is a testing ground for features and compatibility, while the latter is the patch that must be applied on schedule. Mixing the two into a single deployment mandate will only cause genuinely urgent security patches to be buried.</p>
<h4>Verification Checklist (Suggested by This Publication)</h4>
<ol>
<li>In <strong>Settings &gt; Windows Update &gt; View update history</strong>, confirm whether the device has <strong>KB5124010</strong> installed.</li>
<li>Play a piece of <strong>AC-3 / Dolby Digital</strong> content to verify (e.g., a Blu-ray player or a game supporting Dolby Digital), and record the current <strong>OS build</strong> in <strong>Settings &gt; System &gt; About</strong>, comparing it against the patch baseline.</li>
<li>Return to <strong>Windows Update</strong> to install the subsequent corrective cumulative update, then <strong>re-test AC-3 playback</strong>; only after passing should you re-certify, and log the results in a change record noting the <strong>KB number, build number, and test content source</strong>. If any content still crashes, execute rollback or uninstall <strong>KB5124010</strong> immediately.</li>
</ol>

<h3>Windows 11 預覽更新 KB5124010 引致 Dolby Digital 應用程式崩潰，微軟另發修正更新</h3>
<p>微軟已解決一項由 <strong>KB5124010</strong> 引入的缺陷：裝置安裝 2026 年 9 月 Windows 11 預覽更新後，所有依賴 <strong>AC-3（Dolby Digital）</strong> 音訊解碼的遊戲與媒體應用程式會立即崩潰。修復並非透過 KB5124010 本身，而是由 Windows Update 另行推送的一個後續修正累積更新（corrective cumulative update）；該修正更新的 KB 編號目前尚未公布。</p>
<h4>首要前提：這不是安全更新</h4>
<p><strong>KB5124010 屬於預覽更新，本身不含任何安全修補。</strong> 由於這次缺陷只源自 KB5124010，未安裝該更新的裝置並未因此引入額外風險，亦無需為了這次事故補裝 KB5124010。</p>
<p>換言之，這次事故的正確解讀不是「微軟有新補充修補程式要立刻全面上線」，而是處理已經出現崩潰的裝置——以下部署指引即按此原則劃分。</p>
<h4>影響範圍：AC-3 解碼路徑全面受影響</h4>
<p>故障模式相當集中：凡使用 AC-3 / Dolby Digital 解碼路徑的程式，包括 Blu-ray 播放、部分主機移植遊戲以及支援 Dolby Digital 的媒體應用，在套用 KB5124010 後會立即崩潰。由於問題源自 KB5124010，受影響範圍限於已採用九月預覽更新的裝置。</p>
<p>至於確切受影響的 build number，報道並未逐一列明，部署前應以裝置實際 build 為準。</p>
<h4>修復與交付途徑</h4>
<p>微軟的補救方式是另一個獨立的修正累積更新，經 Windows Update 正常渠道發放。管理員應在 Windows Update 檢查有無新的累積更新可用。</p>
<h4>部署指引（本刊分析）</h4>
<p>以下為本刊按報道內容整理的部署參考，供 IT 管理員評估：</p>
<p><strong>1. 已安裝 KB5124010（出現崩潰）</strong>
盡快套用 Windows Update 中的修正累積更新；若修正尚未到位，可先解除安裝 KB5124010，延至下一個既定維護周期再重試。</p>
<p><strong>2. 未安裝 KB5124010（未受影響）</strong>
無需採取任何行動。不主動採用這個預覽更新，交由下一個正式安全更新周期自然跟進。</p>
<p><strong>3. 已將預覽更新推送至正式環境</strong>
先核對實際 build number，重新測試 AC-3 播放，確認無誤後才重新認證部署；在完成 AC-3 回歸測試之前，不應將這批裝置標記為合規。</p>
<h4>修補管理層面的啟示</h4>
<p>這次事件再次印證預覽更新與安全更新的風險性質完全不同：前者是功能與相容性的試驗場，後者才是必須按時套用的修補程式。將兩者混入同一條部署指引，只會令真正緊急的安全修補程式被淹沒。</p>
<h4>驗證 Checklist（本刊建議）</h4>
<ol>
<li>在 <strong>Settings &gt; Windows Update &gt; View update history</strong> 確認裝置是否已安裝 <strong>KB5124010</strong>。</li>
<li>播放一段 <strong>AC-3 / Dolby Digital</strong> 素材進行驗證（例如 Blu-ray 播放器或支援 Dolby Digital 的遊戲），並在 <strong>Settings &gt; System &gt; About</strong> 記錄目前 <strong>OS build</strong>，與修補基線對照。</li>
<li>返回 <strong>Windows Update</strong> 安裝後續修正累積更新，完成後<strong>重新測試 AC-3 播放</strong>，通過才重新認證，並把結果寫入變更記錄，註明 <strong>KB 編號、build number、測試素材來源</strong>；若任何素材仍然崩潰，立即執行 rollback 或解除安裝 <strong>KB5124010</strong>。</li>
</ol>
