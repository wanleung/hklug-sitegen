Title: Firefox 159 Ships a Fix for Creeping Memory Use on AMD Linux Desktops

<h3>Firefox 159 Ships a Fix for Creeping Memory Use on AMD Linux Desktops</h3>
<p>Mozilla has released Firefox 159, the latest in its bi-weekly cadence of feature updates. For Linux desktop users running AMD graphics, the most practical reason to upgrade is not any headline feature but a long-running complaint: GPU-related memory use that keeps climbing over a long browsing session. Phoronix reported the release on 27 October 2026.</p>
<h4>What was fixed</h4>
<p>According to Phoronix, Firefox 159 addresses "excessive memory use" along the AMD Linux graphics path. In practical terms, that points to memory tied to browser graphics work growing the longer Firefox stays open, eventually exceeding what the loaded tabs alone would justify.</p>
<p>The downstream effects are easy to recognise: after several hours of uptime, memory pressure builds, the system leans harder on swap, and under enough pressure the OOM killer may step in. On machines that are already juggling containers, local virtual machines and build toolchains alongside the browser, that kind of creep is especially unwelcome — though the behaviour is not tied to any one workflow.</p>
<p>What remains unsettled is the root cause. The material available at time of writing does not identify a particular Mesa version, an AMDGPU driver version, or a specific GPU family as the culprit. The safest reading is therefore that this is a fix scoped to the "AMD + Linux graphics path" generally, rather than evidence that any one driver build is at fault. Readers should treat claims about a specific component as unconfirmed until Mozilla's own bug notes address them directly.</p>
<h4>When it arrives</h4>
<p>Firefox's bi-weekly release rhythm is familiar to packagers: once upstream ships, distributions normally follow shortly after. Users can update through their distribution's repositories, Mozilla's own repository, a tarball, or Flatpak. To check manually, open Menu → Help → About Firefox to see the installed version and fetch any available update.</p>
<p>Because 159 falls within Mozilla's normal scheduled feature sequence rather than an urgent out-of-band release, there is no sign from the available material of an accompanying security advisory that would force an immediate reboot. That distinction matters for anyone managing machines on a frozen or controlled update schedule: there is no emergency prompting action, but there is also no reason for AMD Linux users to hold back, since the fix itself is about keeping the system stable.</p>
<h4>Bottom line</h4>
<p>If you run Firefox on an AMD Linux desktop, 159 is worth upgrading to promptly — the memory fix is the headline reason. If you are not on AMD hardware, this is simply Mozilla keeping its normal incremental pace, and public details on other changes are limited enough that it does not warrant a special update window.</p>
<p>In short: AMD Linux users should update now; those on tightly managed stable images can wait for their normal update stream to carry the release across.</p>

<h3>Firefox 159 推出：修復 AMD Linux 桌面記憶體持續攀升問題</h3>
<p>Mozilla 已發布 Firefox 159，為其雙星期功能更新節奏中的最新版本。對於使用 AMD 顯示卡的 Linux 桌面用戶而言，升級最切實的理由並非任何矚目的新功能，而是一項長期存在的投訴：GPU 相關記憶體用量會在長時間瀏覽過程中不斷攀升。Phoronix 已於 2026 年 10 月 27 日報道是次發布。</p>
<h4>修復內容</h4>
<p>根據 Phoronix 報道，Firefox 159 針對 AMD Linux 圖形路徑上的「過量記憶體使用」（excessive memory use）問題作出修正。就實際情況而言，這指向與瀏覽器圖形運作相關的記憶體佔用會隨 Firefox 開啟時間增加而不斷增長，最終超出已載入分頁本身應有的水平。</p>
<p>後果易於察覺：系統運行數小時後，記憶體壓力逐步升高，系統會更頻繁依賴 swap，壓力足夠大時更可能觸發 OOM killer。對於本身已同時運行 containers、本地虛擬機及編譯工具鏈的電腦而言，此類增長尤其不受歡迎——雖然此行為並非某一種特定工作流程所獨有。</p>
<p>仍未釐清的是根本原因。撰稿時可得的資料並未指出特定 Mesa 版本、AMDGPU 驅動版本或具體 GPU 系列為肇因。因此，最穩妥的解讀是：這是範圍涵蓋「AMD ＋ Linux 圖形路徑」的整體修正，而非任何特定驅動版本存在缺陷的證據。在 Mozilla 自身的 bug 註記直接就此事作出說明之前，讀者宜將涉及具體元件的說法視為未經確認。</p>
<h4>更新時機</h4>
<p>Firefox 的雙星期發布節奏為打包者所熟知：上游一旦發布，各發行版通常隨後跟進。用戶可透過所屬發行版的 repository、Mozilla 官方 repository、tarball 或 Flatpak 進行更新。如欲手動檢查，可開啟 Menu → Help → About Firefox，以查看已安裝版本並取得可用更新。</p>
<p>由於 159 屬於 Mozilla 正常排程的功能更新序列，而非額外的緊急發布，可得資料中並無跡象顯示另有需要即時重新啟動的安全公告。此區別對管理採用凍結或受控更新排程的系統而言相當重要：目前沒有需要即時行動的緊急情況，但 AMD Linux 用戶亦沒有理由延遲更新，因為該項修復本身正是為了維持系統穩定。</p>
<h4>總結</h4>
<p>若在 AMD Linux 桌面上使用 Firefox，159 值得儘快升級——記憶體修復正是主要原因。若並非使用 AMD 硬件，此次發布只是 Mozilla 維持正常漸進更新步伐，而其他改動的公開資料相當有限，未有為此另行安排更新窗口的必要。</p>
<p>總括而言：AMD Linux 用戶應即時更新；採用嚴格管理穩定映像的用戶，則可等待既定更新渠道隨後推送是次版本。</p>
