Title: Zellij 0.46 Arrives With a New Trick: Running as a Desktop Terminal Itself
Content:
<p>```</p>
<p>Zellij, the Rust-based terminal workspace, has shipped version 0.46 with a change that pushes it beyond the category it is usually filed under: the multiplexer can now act as a desktop terminal in its own right.</p>
<p>LWN.net, which covered the release, reports the headline addition as a new mode invoked with <code>zellij terminal</code>. In that mode Zellij runs as a standalone emulator rather than a program nested inside one — and, according to the announcement, it does so on Linux, macOS and Windows.</p>
<h4>One binary, two roles</h4>
<p>The more consequential detail for existing users is what did <em>not</em> change. LWN's summary of the announcement is explicit: nothing changes for the normal multiplexer, Zellij can still run inside another terminal, and both entry points produce the same session. In other words, the desktop-terminal capability is an addition to the entry point, not a fork of the project — a workspace opened the traditional way and one opened via <code>zellij terminal</code> are the same kind of session.</p>
<p>For teams with invested configurations, that means existing layouts and keybindings can carry over as the standalone mode is adopted incrementally.</p>
<h4>Also in 0.46</h4>
<p>Alongside the desktop-terminal mode, the release adds a GUI settings screen, session previews, and a right-click menu. LWN also points readers to a walkthrough for more on the 0.46 release.</p>
<h4>Where it sits in the terminal stack</h4>
<p>Terminal emulators — GNOME Terminal, Alacritty, WezTerm, Windows Terminal — handle rendering, fonts, and scrollback. Multiplexers — tmux, GNU Screen, Zellij itself — handle panes, windows, and detachable sessions. Most users run one inside the other. Zellij 0.46 ships both roles in a single Rust binary spanning three desktop operating systems.</p>
<p>For readers working across mixed Linux servers and macOS or Windows workstations, the cross-platform parity means one configuration model and one set of keybindings can follow a user from a jump host to a laptop, rather than maintaining separate habits on server and desktop.</p>
<p>Compared with tmux or GNU Screen, Zellij already differentiated itself on defaults — an opinionated, discoverable UI rather than a blank prompt — and 0.46 extends that to the emulator layer. Session-resume workflows, pane persistence, and attach/detach semantics remain the shared core; the new mode simply removes the need to install a separate emulator underneath.</p>
<h4>Availability</h4>
<p>Version 0.46 is available from the project's repository, with source and release artifacts published by the Zellij team.</p>
<p>For an open-source project that has spent its life in the multiplexer niche, 0.46 expands Zellij's scope beyond the multiplexer.</p>

<p>以 Rust 編寫的終端機工作區 Zellij 已發布 0.46 版，一項改動令它超越了本身所屬的類別：這個 terminal multiplexer 現在可以獨立化身為桌面終端機。</p>
<p>LWN.net 報導是次發布，指最矚目的新增功能是以 <code>zellij terminal</code> 啟動的新模式。在該模式下，Zellij 以獨立模擬器（emulator）方式運行，而非嵌套在另一個模擬器之內的程式——據公告所述，它同時支援 Linux、macOS 和 Windows。</p>
<h4>一個 binary，兩種角色</h4>
<p>對現有用戶而言，更具意義的細節是<em>沒有</em>改變的部分。LWN 對該公告的概述寫得明白：一般 multiplexer 行為完全不變，Zellij 照舊可以在另一個終端機之內運行，而兩個入口點產生的是同類型的 session。換言之，桌面終端機功能只是入口點上的新增，而非項目的分叉——以傳統方式開啟的工作區，與透過 <code>zellij terminal</code> 開啟的工作區，屬於同一類型的 session。</p>
<p>對於已有成熟配置的團隊而言，這代表在逐步採用獨立模式時，現有的 layout 和 keybinding 可以沿用。</p>
<h4>0.46 的其他內容</h4>
<p>除桌面終端機模式外，是次發布還加入圖形化設定畫面、session 預覽，以及右鍵選單。LWN 另有連結，帶讀者瀏覽介紹 0.46 版本更多內容的 walkthrough。</p>
<h4>在終端機架構中的位置</h4>
<p>終端機模擬器——GNOME Terminal、Alacritty、WezTerm、Windows Terminal——負責渲染、字體和 scrollback。多工器——tmux、GNU Screen、Zellij 本身——負責 pane、window 和可分離的 session。大多數用戶是在其中一個之內運行另一個。Zellij 0.46 以單一 Rust binary 同時提供這兩種角色，橫跨三個桌面操作系統。</p>
<p>對於在混合 Linux 伺服器與 macOS 或 Windows 工作站之間工作的讀者，跨平台一致性意味著一套配置模式、一套 keybindings，可以由 jump host 一路跟隨用戶到 laptop，而毋須在伺服器和桌面上分別維持兩套習慣。</p>
<p>與 tmux 或 GNU Screen 相比，Zellij 本已以預設值作出區隔——採用有主見、易於發掘的 UI，而非一片空白提示——而 0.46 將這優勢延伸至模擬器層。Session 續接（resume）工作流程、pane 持久性以及 attach/detach 語意依然是共同核心；新模式只是省卻了在底層另行安裝模擬器的需要。</p>
<h4>發行情況</h4>
<p>0.46 版可從項目的 repository 取得，源碼與發行產物由 Zellij 團隊發布。</p>
<p>對於一個一生都囿於 multiplexer 利基市場的開源項目而言，0.46 將 Zellij 的範疇擴展至 multiplexer 以外。</p>
