<h3>KDE Ships First Release of Kwi, a Terminal Built on Ghostty's Library</h3>
<p>KDE has shipped the first release of Kwi, a new terminal emulator built on the Ghostty library, according to Phoronix. The project has been under development over recent weeks, and the release marks its move from prototype to something users can actually install and test — while raising an early question for anyone who has settled into Konsole, kitty, or Alacritty: is it worth switching?</p>
<p>The headline claim is speed. KDE developers say Kwi delivers what the project describes as "magnificent performance" over Konsole, the terminal that has shipped with the KDE desktop for more than twenty years. Phoronix's coverage did not include benchmark figures or a complete feature list, however, so the size of that performance gap is not yet independently clear. Users evaluating Kwi will need to run their own comparisons — particularly those working with large build logs, multiplexed sessions, or fast-scrolling output, where terminal rendering differences tend to show up most.</p>
<p>The more consequential story is architectural. Rather than continuing to evolve Konsole's in-house emulation and rendering stack, KDE's developers have chosen to build on the Ghostty library — the reusable core beneath Mitchell Hashimoto's Ghostty terminal, which reached 1.0 in late 2024. Ghostty was designed from the outset to separate its terminal engine from the application wrapped around it, and Kwi appears to be among the first desktop-environment-scale projects to exploit that split directly. KDE gains rendering, input handling, and emulation work without inheriting Ghostty's interface, branding, or release schedule.</p>
<p>That arrangement matters beyond a single application. Terminal emulation is expensive to solve well, and when one project solves it in a library, every downstream adopter inherits the improvement. If Kwi holds up in real use, it strengthens the case for rebuilding mature desktop components on shared foundations rather than maintaining bespoke code — a pattern that could influence how other KDE components are approached in future.</p>
<p>For developers comparing terminals today, the practical reality is that a first release is an early milestone, not a finished product. Konsole's depth — tab management, split views, profiles, session handling, and two decades of accumulated refinements — will not be matched on day one. The near-term test for Kwi is whether Ghostty's speed advantages survive integration into Plasma: native theming, Wayland behaviour, and KDE's own framework expectations all sit on top of the library once it lands in the desktop. Whether Kwi eventually becomes KDE's default terminal or coexists alongside Konsole as an alternative remains unanswered; KDE has announced no such plan.</p>
<p>Release versioning and packaging status were not detailed in the source coverage, so distribution availability is best confirmed through individual repositories or KDE's own channels before treating Kwi as a daily driver.</p>
<p>Even so, the release is a clear signal. It shows KDE is willing to source core technology from outside its own tree, and it marks Ghostty's library beginning to operate as shared infrastructure for projects well beyond its original application. For Linux desktop users weighing Konsole against kitty and Alacritty, the choice just gained another serious contender — one worth benchmarking rather than taking on faith.</p>

<h3>KDE 推出 Kwi 首個版本，基於 Ghostty 函式庫構建的終端機</h3>
<p>據 Phoronix 報道，KDE 已推出 Kwi 的首個版本，這是一款基於 Ghostty 函式庫構建的全新終端機模擬器。該項目過去數週一直在開發之中，此次發布標誌著它由原型階段邁向用戶可實際安裝及測試的產品——同時亦為已習慣使用 Konsole、kitty 或 Alacritty 的用戶提出一個早期疑問：是否值得轉換？</p>
<p>主要賣點在於速度。KDE 開發者表示，Kwi 相對於 Konsole（這款終端機已隨 KDE 桌面發布逾二十年）達到項目所稱的「卓越性能」。然而，Phoronix 的報道並未包含基準測試數據或完整的功能列表，因此該性能差距的實際幅度尚未獲得獨立釐清。評估 Kwi 的用戶需要自行進行比較——尤其是處理大型建置日誌、多工分割階段或快速滾動輸出的用戶，終端機渲染差異往往在這些情境中最為明顯。</p>
<p>更重要的是架構上的轉變。KDE 開發者沒有選擇繼續發展 Konsole 自家的模擬及渲染技術堆疊，而是決定基於 Ghostty 函式庫構建——這是 Mitchell Hashimoto 的 Ghostty 終端機底下的可重用核心，Ghostty 已於 2024 年底達到 1.0 版本。Ghostty 設計之初即著重將終端機引擎與外圍應用程式分離，而 Kwi 似乎是首批直接利用這一拆分架構的桌面環境級別項目之一。KDE 由此獲得渲染、輸入處理及模擬方面的成果，同時無需承繼 Ghostty 的介面、品牌或發布節奏。</p>
<p>這一安排的影響不限於單一應用程式。終端機模擬要處理得好成本高昂，當某個項目將其實現於函式庫之中，所有下游採用者都能繼承這項改進。如果 Kwi 在實際使用中站穩腳跟，便會增強以共享基礎重構成熟桌面組件的理據，取代維護專屬代碼的做法——此模式或影響日後其他 KDE 組件的發展方向。</p>
<p>對於今日正比較終端機的開發者而言，現實情況是首個版本只是早期里程碑，而非成品。Konsole 的深度——分頁管理、分割視圖、設定檔、工作階段管理，以及二十年累積的種種完善——不可能在第一天就被追上。Kwi 近期的考驗在於 Ghostty 的速度優勢能否在整合至 Plasma 後依然成立：原生主題、Wayland 行為，以及 KDE 自身的框架期望，一旦該函式庫進入桌面便全都構成其上層負擔。Kwi 最終會否成為 KDE 的預設終端機，抑或與 Konsole 並存作為替代選項，目前尚無答案；KDE 並未宣布任何此類計劃。</p>
<p>原始報道並未詳述發布版本號及打包狀態，因此在將 Kwi 用作日常工具之前，最好先透過各發行版的軟件庫或 KDE 自身渠道確認可用性。</p>
<p>儘管如此，此次發布是一個明確信號。它顯示 KDE 願意從自身代碼樹以外引入核心技術，亦標誌著 Ghostty 的函式庫開始作為共享基礎設施，服務遠超其原有應用程式範圍的項目。對於正在 Konsole、kitty 及 Alacritty 之間取捨的 Linux 桌面用戶而言，選擇又多了一個有力的競逐者——值得以基準測試驗證，而非盲目信賴。</p>
