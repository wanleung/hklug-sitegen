Title: LiberNT Forks ReactOS, Betting AI Can Shortcut the Years-Long Road to Windows 11 Compatibility
Content:
<p>A new open-source project called LiberNT has emerged as a fork of the long-running ReactOS codebase, carrying a stated ambition that would have sounded implausible a few years ago: using AI-assisted development to compress what has traditionally been years of compatibility engineering into months, with the goal of running Windows 11 workloads. Phoronix, which reported the project's appearance, describes it as an AI-fueled fork of ReactOS focused specifically on Windows 11 compatibility.</p>
<p>The framing matters more than the project's branding. ReactOS — a volunteer effort to reimplement the Windows NT architecture as a free, open-source operating system — has been making conventional, hard-won progress this year, including initial USB 3.0 driver support and improvements to its DirectX implementation. LiberNT does not replace that work; it forks it, and layers a different development methodology on top: AI-driven iteration applied to a codebase where correctness has always been the binding constraint.</p>
<p>That distinction is where the story stops being niche OS news and becomes a test case for where AI can realistically contribute in systems programming. Getting a kernel to compile and boot is a far smaller achievement than getting it to run an unmodified application correctly. ReactOS's entire value proposition rests on surviving edge cases in application binary interfaces (ABI), kernel-mode behaviour, and the accumulated quirks of undocumented Windows semantics. A change that looks correct but silently corrupts state is worse than no change at all — a regression wearing a feature's clothes.</p>
<p>The "years into months" claim, as reported by Phoronix, originates from LiberNT's own materials rather than from independent benchmarking, and the project is understood to be at an early stage. Whether its AI-generated changes can survive ReactOS's compatibility test suites — the real credibility standard in this space — remains to be seen. No first-party repository or announcement has been independently confirmed, and the parent ReactOS project has not, as far as is publicly known, commented on the fork.</p>
<p>Forking is also a strategic choice with a cost attached. By stepping outside the upstream project, LiberNT avoids what would likely be a protracted governance debate about landing AI-generated code into a security-sensitive, GPL-licensed system that reconstructs Microsoft's undocumented behaviour. But a fork that diverges rapidly makes eventual reintegration impractical, and a fork that diverges slowly has to justify its existence against upstream ReactOS itself. Either way, the project faces a reintegration-versus-justification dilemma — and neither path is free.</p>
<p>The outcome is informative either way. If LiberNT demonstrably accelerates compatibility work at the kernel and ABI layer, it establishes that AI can contribute meaningfully to one of the most demanding categories of open-source engineering. If it stalls — or ships changes that pass superficial testing but fail real applications — it draws a useful boundary marker for where deep human expertise remains irreplaceable.</p>
<p>For IT professionals managing device fleets with legacy Windows-dependent applications, the story is worth watching as a general trend rather than a near-term tool: the combination of entrenched legacy software and enterprise licensing pressure keeps demand alive for credible open-source Windows compatibility layers, and any project that genuinely shortens that timeline would be relevant to long-term platform planning. LiberNT, at alpha stage and resting largely on its own claims, is not yet that project — but it is an experiment worth tracking as the first serious attempt to apply AI methodology to the NT compatibility problem.</p>
<hr>
<p>一個名為 LiberNT 的新開源項目，近日以長年運作的 ReactOS 代碼庫的 fork 形式登場，其宣稱的目標在數年前聽來恐怕難以置信：透過 AI 輔助開發，將傳統上需時多年的相容性工程壓縮至數月內完成，最終目標是運行 Windows 11 工作負載。率先報導該項目出現的 Phoronix，形容它是一個由 AI 驅動的 ReactOS fork，專注於 Windows 11 相容性。</p>
<p>這裡的定位比項目本身的命名更為重要。ReactOS 是一項以自由、開源作業系統重新實作 Windows NT 架構的志願者計劃，今年一直取得穩紮穩打、來之不易的進展，包括初步支持 USB 3.0 驅動程式，以及改進其 DirectX 實作。LiberNT 並非取代這項工作，而是將其 fork，並在之上疊加另一套開發方法論：在一個一直以正確性為最嚴格約束條件的代碼庫上，應用 AI 驅動的迭代開發。</p>
<p>正是這一點區分，令事件由小眾作業系統新聞，升格為一個測試案例——檢視 AI 在系統編程領域究竟可以如何切實地作出貢獻。讓一個 kernel 編譯並啟動，與讓它正確運行一個未經修改的應用程序，兩者成就相距甚遠。ReactOS 的整個價值主張，取決於它能否應對應用程序二進制接口（ABI）、kernel mode 行為，以及 Windows 未公開語義所積累的各種古怪之處。一項看似正確卻悄悄損壞狀態的改動，比完全沒有改動更糟糕——那是披著功能外衣的 regression。</p>
<p>按 Phoronix 所述，「多年變成數月」的說法源自 LiberNT 自身的材料，而非獨立基準測試，而項目據悉仍處於早期階段。其 AI 生成的改動能否通過 ReactOS 的相容性測試套件——才是這一領域真正公信力的標準——仍有待觀察。目前尚無第一方 repository 或官方公告獲得獨立確認，而母項目 ReactOS 據公開所知亦未就此次 fork 作出評論。</p>
<p>Fork 本身也是一項附帶代價的戰略選擇。脫離上游項目，LiberNT 避免了一場勢必曠日持久的治理爭論：是否應將 AI 生成的代碼納入一個安全性敏感、採用 GPL 授權、並重建 Microsoft 未公開行為的系統。然而，偏離過快的 fork 會令最終重新整合變得不切實際，而偏離緩慢的 fork 則必須不斷論證自身相對於上游 ReactOS 存在的理由。無論如何，項目都面臨重新整合與自我論證的兩難——而兩條路都代價不菲。</p>
<p>無論結果如何，都有參考價值。若 LiberNT 能確切證明自己加速了 kernel 與 ABI 層面的相容性工作，便確立了 AI 可以對開源工程中最苛刻的類別之一作出實質貢獻。若它停滯不前——或推出通過表面測試卻無法運行實際應用的改動——則為人類深度專業知識仍然無可替代的領域，劃下了一條有用的界線。</p>
<p>對於管理配備依賴舊版 Windows 應用程序之機隊的 IT 專業人士而言，這件事值得作為整體趨勢而非近期可用工具來持續關注：根深蒂固的舊版軟件結合企業授權壓力，令市場對可信的開源 Windows 相容層的需求持續存在，任何真正縮短這一時間表的項目，都與長期平台規劃息息相關。LiberNT 目前處於 alpha 階段，很大程度上仍依賴自身的宣稱，尚未成為那個項目——但作為首次將 AI 方法論認真應用於 NT 相容性問題的嘗試，它是一個值得追蹤的實驗。</p>
