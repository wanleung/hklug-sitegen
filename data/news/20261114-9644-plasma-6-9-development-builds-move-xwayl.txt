<h3>Plasma 6.9 Development Builds Move XWayland to On-Demand Launch, Add New Wobbly Windows Presets</h3>
<p>Development builds of KDE Plasma 6.9 will soon allow XWayland to start only when needed, replacing the current practice of keeping it running for the life of most Wayland sessions; the same progress roundup also brings new Wobbly Windows effect presets. The change is particularly relevant for developers who rely on legacy X11 tools alongside native Wayland applications.</p>
<p>Phoronix reports that KDE's weekly progress digest, "This Week in Plasma," says the in-development change in Plasma 6.9 shifts XWayland from "always on after login" to "summoned on demand." The series has long tracked features that have not yet shipped officially, so details in the report may still change before release.</p>
<h5>What XWayland Is, and What the Change Affects</h5>
<p>XWayland is the compatibility layer that lets X11 applications run inside a Wayland session. In the Plasma Wayland default on most distributions today, XWayland starts at login and keeps running — even if a user's entire workflow uses only native Wayland apps. With on-demand startup, it will appear only when an X11 application is actually opened. In other words, even with no X11 apps on the desktop, the layer will no longer sit permanently in the process list.</p>
<h5>What It Means for Developers and Administrators</h5>
<ul>
<li><strong>Cleaner mixed workflows</strong>: Developers who still need to run legacy X11 tools — such as some build or debugging utilities that have not yet been ported — keep their compatibility, while the native Wayland environment no longer carries an unnecessary resident layer.</li>
<li><strong>A third option for administrators</strong>: The previous deployment choice was between "give everyone a full X11 session" and "keep XWayland resident by default for everyone." On-demand mode offers a middle path.</li>
<li><strong>More predictable overhead and behaviour</strong>: The process list more closely reflects actual usage, which makes debugging and monitoring easier.</li>
</ul>
<h5>Upgrade Path and Open Questions</h5>
<p>Plasma 6.9 is still under development. When the on-demand default will switch over, and whether individual distributions can override it, remains undecided; users on fixed-version upgrade paths such as Fedora KDE and Kubuntu may see different behaviour depending on packaging decisions. These details are worth re-checking against KDE's release notes before the official launch.</p>
<p>The source report does not cover how GNOME handles the equivalent, and any comparison awaits further verification from upstream documentation.</p>
<h5>New Wobbly Windows Presets</h5>
<p>The same progress roundup also notes that Wobbly Windows has gained several new effect presets — the classic rubber-band window effect returning in a new form under Wayland. For developers, on-demand XWayland trims resident overhead; Wobbly Windows is the visual flourish the desktop environment still chooses to keep.</p>

<h3>Plasma 6.9 開發版擬把 XWayland 改為按需啟動，另增抖動視窗特效預設值</h3>
<p>KDE Plasma 6.9 開發版即將允許 XWayland 只在需要時才啟動，取代目前在多數 Wayland 工作階段中常駐運行的做法；同一期進度彙整還帶來新的 Wobbly Windows（抖動視窗）特效預設值。這項改動對同時依賴舊式 X11 工具與原生 Wayland 應用的開發者尤其實際。</p>
<p>Phoronix 報導，KDE 每週固定發佈的進度彙整「This Week in Plasma」指出，Plasma 6.9 正在開發中的這項變更讓 XWayland 從「開機即常駐」改為「按需召喚」。該系列長期追蹤尚未正式發行的開發中功能，因此報導中的細節仍可能在上市前調整。</p>
<h5>XWayland 是什麼，改動又影響什麼</h5>
<p>XWayland 是讓 X11 應用程式在 Wayland 工作階段上運行的相容層。在目前多數發行版的 Plasma Wayland 預設中，XWayland 會在登入後就啟動並持續運行——即使使用者整個工作流程都只開原生 Wayland 應用。改為按需啟動後，它只會在真正開啟 X11 應用時才出現。換言之，即使桌面上沒有任何 X11 應用，這層相容層也不會再一直存在於程序列表中。</p>
<h5>對開發者與管理員的實際意義</h5>
<ul>
<li><strong>混用工作流更乾淨</strong>：仍需執行舊式 X11 工具（例如部分尚未移植的建置或除錯工具）的開發者不失去相容性，同時原生 Wayland 環境不再背負不必要的常駐層。</li>
<li><strong>管理員多一個選項</strong>：過去部署時的取捨是「給所有人完整 X11 工作階段」或「所有人預設常駐 XWayland」，按需模式提供了第三條路。</li>
<li><strong>開銷與行為更可預期</strong>：程序列表更貼近實際使用狀態，便於除錯與監控。</li>
</ul>
<h5>升級路徑與仍未確定的事項</h5>
<p>Plasma 6.9 尚在開發階段。預設何時切換為按需啟動、以及個別發行版能否覆蓋此預設，目前都未有定論；透過 Fedora KDE、Kubuntu 等固定版本升級路徑取得 Plasma 的使用者，實際行為可能因發行版的打包決定而異。這些細節值得在正式發行前對照 KDE 發佈說明再確認一次。</p>
<p>來源報導並未涉及 GNOME 的對應做法，任何比較均有待上游文件進一步查證。</p>
<h5>Wobbly Windows 新預設值</h5>
<p>同一期進度彙整還提到 Wobbly Windows 新增了若干特效預設值——這個經典的橡皮筋視窗效果在 Wayland 時代以新形式回歸。對開發者而言，按需 XWayland 減省的是常駐開銷；Wobbly Windows 則是桌面環境在功能性之外保留的視覺趣味。</p>
