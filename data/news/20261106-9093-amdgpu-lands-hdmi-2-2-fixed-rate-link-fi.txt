Title: AMDGPU lands HDMI 2.2 Fixed Rate Link fixes as Linux 7.4 display work wraps up
Content:
<p>```</p>
<p>The AMDGPU driver is set to arrive in Linux 7.4 with a notably more complete HDMI story, according to Phoronix, which reports that fixes improving Fixed Rate Link (FRL) support against the newer HDMI 2.2 specification are queued for the release. They land on top of changes already in the cycle that make HDMI 2.1 FRL functionality the default for driving higher-resolution and higher-refresh-rate displays, alongside HDMI FreeSync/VRR and Auto Low Latency Mode (ALLM) support.</p>
<p>For AMD GPU users on Linux, the practical upshot is that the features most people expect from a modern HDMI connection — 4K at high refresh rates, variable refresh for gaming, and latency-reduction signalling for TVs and consoles — are moving from opt-in or partial states toward working out of the box on a supported kernel.</p>
<p>A quick point of technical history matters here, because it explains why two HDMI generations appear in the same patch series. FRL itself debuted with HDMI 2.1, replacing the older TMDS signalling with a scalable, packet-based link capable of more bandwidth. HDMI 2.2, announced at CES 2025, extends that same FRL architecture to higher link rates rather than introducing an entirely new physical layer. The fixes heading into Linux 7.4 therefore address the same amdgpu code path — negotiation and link training against the rates the newer spec allows — which is why HDMI 2.1's default-enabling and the HDMI 2.2 corrections are landing together.</p>
<p>The sequencing also has distribution implications. Merge-window landings like this typically reach users in stages: raw kernel builds and rolling-release distributions tend to pick up new kernels quickly, while fixed-release enterprise and LTS distributions generally wait for stable point releases before backporting. Users on those conservative channels may be waiting a release cycle or two before the FRL-by-default behaviour shows up without manual intervention.</p>
<p>That timeline will be worth watching for a profile that will be familiar to many readers here, whether wiring an AMD desktop to a living-room TV or driving a high-refresh monitor — since the practical benefit depends less on the driver patch itself than on when a packaged kernel carrying it lands on their machine.</p>
<p>It is also worth setting expectations: FRL enabled by default does not guarantee every display improves on day one. Link training still depends on cable quality and display firmware, so a stubborn panel may behave no differently after an upgrade than it did before.</p>
<p>What makes this story significant beyond the individual features is how much display-protocol plumbing AMDGPU has had to straighten out in a single cycle — FreeSync/VRR, ALLM, default FRL, and now forward compatibility with the HDMI 2.2 rates announced at CES 2025. Individually, none of these is headline-grabbing; together they close out a long-running effort to make the open-source driver's HDMI output behave predictably.</p>
<p>More detail is available in the original report at <a href="https://www.phoronix.com/news/AMDGPU-HDMI-2.2-FRL-Fixes">Phoronix</a>.</p>
<hr>
<p>據 Phoronix 報導，AMDGPU 驅動程式將隨 Linux 7.4 發布，HDMI 支援方面明顯更為完整，當中一系列改進 Fixed Rate Link（FRL）以配合較新 HDMI 2.2 規範的修正已排隊等候納入是次版本。這些修正建立於本輪合併視窗已有改動之上——令 HDMI 2.1 FRL 功能成為驅動更高解析度及更高更新率顯示器的預設設定，同時亦包含 HDMI FreeSync/VRR 及 Auto Low Latency Mode（ALLM）支援。</p>
<p>對 Linux 上的 AMD GPU 用戶而言，實際效果在於：大部分人對現代 HDMI 連接的期望功能——高更新率下的 4K 輸出、遊戲用可變更新率，以及電視和遊戲主機的延遲降低信號——正由需要手動啟用或僅部分可用的狀態，逐步邁向在受支援的核心上開箱即用。</p>
<p>這裡有一段技術歷史值得先說明，因為它解釋了為何兩代 HDMI 會同時出現在同一個 patch 系列中。FRL 本身隨 HDMI 2.1 首度登場，以可擴展、基於封包的連接取代較舊的 TMDS 信號方式，提供更高頻寬。至於在 CES 2025 公布的 HDMI 2.2，只是把同一套 FRL 架構延伸至更高的 link rate，並非引入全新的 physical layer。因此，納入 Linux 7.4 的修正針對的是同一段 amdgpu 代碼路徑——就新規範所允許的速率進行協商及 link training——這正是 HDMI 2.1 的預設啟用與 HDMI 2.2 修正會一同落地的原因。</p>
<p>發布先後次序亦帶有發行版層面的影響。此類 merge window 的改動通常會分階段抵達用戶：raw kernel 及 rolling-release 發行版一般會迅速採用新核心，而固定版本的企業級及 LTS 發行版通常會等待穩定的 point release 才作 backport。走這些保守渠道的用戶，可能要等上一個甚至兩個發布周期，才會在無需手動介入的情況下見到 FRL 預設啟用的行為。</p>
<p>這個時間表值得留意，因為不少讀者都會遇到相似情境——無論是把 AMD 桌機接上客廳電視，還是驅動一台高更新率顯示器——因為實際得益與其說取決於驅動程式 patch 本身，不如說取決於載有該 patch 的封裝核心何時會到達他們的機器上。</p>
<p>同時亦要管理好預期：FRL 預設啟用並不保證每一台顯示器在首日便有所改善。Link training 仍取決於線材質素及顯示器 firmware，一塊頑固的 panel 升級後的表現可能與升級前無異。</p>
<p>這則新聞超越個別功能的重要性，在於 AMDGPU 在單一周期之內需要理順多少顯示協議層面的基建——FreeSync/VRR、ALLM、預設 FRL，以及如今對 CES 2025 公布的 HDMI 2.2 速率的向前兼容。逐一來看，這些都不足以登上頭條；但合在一起，它們為一項持續已久的工程畫上句號——令這套開源驅動的 HDMI 輸出表現變得可預期。</p>
