<h3>Linux NTFS 驅動即將支援替代資料流（ADS）：檔案搬移、備份與取證的關鍵一步</h3>
<p>Linux 核心的現代 NTFS 驅動程式（ntfs3）即將加入對替代資料流（Alternate Data Streams，簡稱 ADS）的支援。根據 Phoronix 報導，這批改動預計隨 Linux 7.4 合併進核心；該驅動本身是在 Linux 7.1 才納入核心的，之後一直有新功能與修正持續進來。</p>
<h4>什麼是替代資料流？</h4>
<p>ADS 是 NTFS 檔案系統的一項特性：同一個檔案除了主要內容之外，還可以掛上多個「隱藏」的附加資料流，每個流有自己的名稱，例如 <code>report.docx:owner</code> 或 <code>report.docx:zone</code>。使用者在 Windows 的檔案總管裡通常看不到它們，但系統與應用程式經常依賴它們運作。最常見的例子是 <code>Zone.Identifier</code> 標記——當你從網路上下載檔案，Windows 會把「這個檔案來自網路」的資訊寫進這個資料流，SmartScreen 等安全功能據此判斷是否要對使用者發出警告。</p>
<h4>對實際工作為何重要</h4>
<p><strong>檔案搬移與備份完整性。</strong> 在 Windows/Linux 混合環境中，只要用不支援 ADS 的工具複製或打包 NTFS 檔案，附加資料流就會被靜默丟棄。搬移後的檔案「看起來一樣」，但依賴這些流的資訊已經消失——備份還原後的檔案可能與原檔並不等價，而這種差異往往無聲無息。驅動層面若能讀寫 ADS，在 Linux 上進行的搬移、同步與備份就有機會保留完整的檔案內容。</p>
<p><strong>NAS 與共用相容性。</strong> 不少跨平台共用、檔案伺服器與同步方案，底層其實掛載 NTFS，或需要處理從 Windows 端複製過來的檔案。若 Linux 端無法正確處理 ADS，Windows 端使用者就會遇到功能失效、或資料悄悄缺損的問題。</p>
<p><strong>安全與數位取證。</strong> 取證人員與安全分析師經常把 ADS 視為證據或威脅的藏匿點——惡意程式可能利用附加資料流存放 payload，一般工具不易察覺。Linux 工具鏈若看不到這些流，掃描與鑑識結果就不完整。能夠在 Linux 下列出並讀取（必要時寫入）ADS，可直接提升取證流程的可信度。</p>
<h4>仍需注意的限制</h4>
<p>需要留意的是，這項功能尚未進入穩定版本，實際落地取決於 Linux 7.4 的合併進度。該驅動雖自 7.1 合併後持續成熟，從「能把 NTFS 掛起來讀」走到「能正確寫入」仍是一段路，現階段並不宜把它當作所有工作負載的萬能方案。至於發行版與 NAS 何時能用上，一般預期仍要等核心穩定版釋出後才會跟進（此點為推測，並非來源報導內容）。</p>
<p>對香港常見的 Windows/Linux 混合環境而言，這項改動的意義不在核心機制本身，而在於它填補了一類長期被忽略、卻極難察覺的資料完整性缺口。</p>
