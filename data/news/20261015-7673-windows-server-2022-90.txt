<h3>Windows Server 2022 主流支援已結束：香港企業的 90 天遷移行動清單</h3>
<p>根據 BleepingComputer 報導，微軟已確認 Windows Server 2022 結束主流支援（mainstream support），系統將繼續享有延伸支援（extended support）至 2031 年 10 月。表面上看，這條時間線長達數年，企業似乎可以從容規劃；但對負責遷移的 IT 團隊而言，真正可用的緩衝期遠比日曆上的日期短——第三方軟硬件認證矩陣、網絡保安保險問卷，以及合規審查，往往會在 2031 年之前就迫使企業採取行動。</p>
<p>以下是一份以 90 天為週期的行動清單，供香港企業參考。所有正式日期與產品細節，仍請以<a href="https://learn.microsoft.com/lifecycle/products/windows-server-2022">微軟官方產品生命週期頁面</a>為準。</p>
<h4>為甚麼「還有五年」是一種錯覺</h4>
<p>延伸支援只保證安全性更新，不代表應用程式供應商、驅動程式廠商或硬件認證仍然支援這個平台。很多合規與網絡保安保險的問卷會直接詢問「是否仍在廠商支援期內的操作系統」，屆時答案未必是技術層面的問題，而是商業層面的問題。與此同時，隨着時間推移，舊世代硬件架構與當前安全設計標準之間的差距只會擴大——平台的實際定位與支援細節，建議直接查閱微軟最新文件確認。</p>
<p>另一個常被低估的成本項是 Extended Security Updates（ESU）。ESU 讓企業在沒有常規更新的年份繼續取得安全性修補，但按年收費，且成本結構可能逐年變化。企業在預算階段應按「可能出現按年遞增」的情景做壓力測試，並向微軟或授權經銷商核實自己實際的授權情況與報價，而不是沿用舊有的批量授權假設。</p>
<h4>第 1–30 天：盤點與成本建模</h4>
<p>列出所有 Windows Server 2022 實例，包括實體機、虛擬機、雲端映像與被遺忘的測試環境。逐一記錄：承載的業務、依賴的線內（LOB）應用程式、外部認證要求，以及硬體保修狀態。同時就 ESU 成本與採購途徑取得書面報價，納入未來數年的預算模型。</p>
<h4>第 31–60 天：兼容性測試與 Azure vs. 自管機房決策</h4>
<p>為每一個 LOB 應用程式建立測試實例，在候選平台上驗證功能、性能與依賴的資料庫版本。這是整項計劃中最容易超時的環節，務必預留緩衝。</p>
<p>與此同時，評估三條路徑：原地升級至較新版本的 Windows Server、把工作負載遷往 Azure 或微軟的混合雲／Azure Local 類方案（具體產品定位、授權與支援細節請以官方文件為準），或是維持現狀並購買 ESU。決策因素通常不是純技術優劣，而是內部維運能力、合規邊界與長期總擁有成本。</p>
<h4>第 61–90 天：採購、合規對接與執行</h4>
<p>鎖定採購與變更窗口，安排測試環境與回滾方案。同步與合規及法律團隊確認相關要求：企業應核對自身所在行業與司法管轄區，對操作系統生命週期的內部政策與外部指引有沒有具體規定，以及這次遷移是否影響現行認證、審計或保險條款。此處僅作提醒，具體義務需由企業按自身牌照與數據情況評估。</p>
<h4>一個現實的收尾</h4>
<p>2031 年 10 月是一個終點，但對多數企業來說，真正決定行動時限的，是供應商認證、保險問卷與合規審查交織而成的實際期限。這段緩衝期很長，卻也有限——而且已經在倒數。</p>
